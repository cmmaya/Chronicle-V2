# BU119 — Persisted UI State And A Safe Preferences File

Status:
Completed

Goal:
Make the app come back the way it was left: the same model, the same session
and scope, the same transcript filter, and the same mute state — and make
`preferences.json` safe to keep that in.

Context:
- Audit of what `preferences.json` holds today (BU119 analysis):
  - saved: `enable_live_transcription`, `auto_summary_after_stop`,
    `detached_window_geometry`, `detached_splitter_sizes`,
    `detached_window_on_top`, and the six `live_qa_*` keys;
  - **not** saved: the selected model, the transcript source filter, the
    selected session and scope, and the BU118 mute state.
- The model selector is the odd one out: `set_selected_model()`
  (`src/config.py`) writes a module global, nothing persists it, and the
  Model Settings dialog tells the user "Changes will persist across
  application restarts". It reverts to `DEFAULT_MODEL` every launch while
  claiming otherwise, and that model drives summarization, the assistant and
  live answers. This is a bug being fixed, not a feature being added.
- `_update_preferences` / `_save_preferences` write with a plain
  `open(path, 'w')` + `json.dump`. A crash or a full disk mid-write truncates
  the file, and `_read_preferences` swallows the parse error and returns `{}`
  - so every setting silently resets with nothing shown to the user. The more
  state this file carries, the worse that failure is, so the write becomes
  atomic in the same BU that adds the keys.
- `preferences.json` is tracked by git, so personal settings churn the repo on
  every toggle. It becomes ignored, and untracked, with the in-code defaults
  (`_load_preferences`, `_load_live_qa_preferences`) remaining the source of
  first-run behaviour - there is no defaults file to keep in sync.
- Mute (BU118) lives on `SessionManager._muted_sources` and is handed to each
  recorder at creation. Persisting it means the app can come back with a dead
  mic, so a restored mute is **announced** at startup rather than only implied
  by a slashed icon.
- The chat conversation deliberately stays fresh: `_current_conversation_id`
  starts at `None` and `_load_past_conversations()` only fills the sidebar
  list. Verified, and unchanged by this BU.
- `_update_scope_label()` is already called from every path that changes the
  scope or the selected session (8 call sites), which makes it the one funnel
  worth persisting from rather than eight separate save calls.

Tasks:
- Safe writes:
  - `_update_preferences` and `_save_preferences` write to a temporary file in
    the same directory and `os.replace` it into place, so an interrupted write
    can never leave a half-written `preferences.json`.
  - A file that fails to parse is still tolerated (`{}`), but the failure is
    logged at warning level with the path, instead of vanishing.
  - Add `preferences.json` to `.gitignore` and stop tracking it. No defaults
    file: the code already defaults every key it reads.
- Selected model (`selected_model`):
  - The Model Settings dialog persists the chosen id.
  - Startup restores it through `set_selected_model()`, which validates
    against `ALLOWED_MODELS`; an unknown or removed id falls back to
    `DEFAULT_MODEL` without raising, and the dialog opens on whatever is
    actually in force.
- Mute state (`muted_sources`):
  - The BU118 toggles persist `{'mic': bool, 'system': bool}`.
  - Startup restores it into `SessionManager` **before** any session is
    created, so the first recording of the run already honours it.
  - A restored mute is announced once through `_on_status_update` naming the
    muted sources, so a session is never recorded silently by accident.
  - A malformed stored value (not a dict, unknown keys, non-boolean) restores
    unmuted rather than raising.
- Transcript source filter (`transcription_filter`):
  - Persist `'all' | 'mic' | 'system'` when the filter changes, restore it at
    startup, and apply it to the view. An unrecognised value falls back to
    `'all'`.
- Selected session and scope (`selected_session_id`, `assistant_scope`):
  - Persist from `_update_scope_label()` - the single funnel every
    scope/selection path already calls - guarded so restoring does not write
    back over what it is reading.
  - Startup restores the scope combo, the session name in the search bar, and
    loads that session's transcripts.
  - If the stored session no longer exists in the database, fall back to "Any
    Session" with no selection, and do not report an error the user cannot act
    on.
  - Restoring must not fight `_on_scope_changed`: reuse the existing
    `_clearing_scope` / guard pattern so the transcripts are loaded once.
- The chat stays new on every start. No restore of `_current_conversation_id`,
  and no change to `_load_past_conversations()`.

Validation Requirements:

Required:
- executable behavior verified
- no syntax/runtime errors
- Definition of Done satisfied
- manual validation:
  - Change the model, restart, and confirm the dialog and the answering path
    both use the chosen model.
  - Mute the mic, restart, and confirm the toggle comes back slashed with a
    startup notice, and that the first recording captures no mic audio.
  - Set the transcript filter to Mic, restart, and confirm it is still Mic.
  - Select a session in Specific Session scope, restart, and confirm the same
    session, scope and transcripts come back.
  - Delete that session, restart, and confirm a clean fall back to Any Session.
  - Restart and confirm the chat is empty with past conversations still listed
    in the sidebar.
  - Corrupt `preferences.json` by hand and confirm the app starts on defaults
    and logs it.

Tests Required:
- yes — atomic write (the file is intact and parseable after a failed write,
  and a partial temp file never replaces it), model round-trip including an
  unknown id, mute round-trip including a malformed value, filter round-trip
  including an unrecognised value, session/scope round-trip including a
  deleted session, that restoring does not write back mid-restore, and that
  the chat conversation id is never restored

Out of Scope:
- Reopening the detached transcripts window on startup
- Persisting main-window geometry or sidebar collapse state
- Persisting chunk selection, find-bar state or the BU117 reference document
- Any per-session (as opposed to per-user) settings store
- Moving preferences to a database table or a platform config directory
