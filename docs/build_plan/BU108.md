# BU108 — Screenshot-Aware Specific Session Answers

Status:
Completed

Goal:
In Specific Session scope, the assistant receives a compact index of the
session's screenshots plus full metadata only for the relevant ones. When an
answer is backed by a screenshot, the assistant points the user to it:
"The information you asked might be contained in the screenshot: #<ID>".

Context:
Today `AssistantContextRetriever._get_screenshots_near_transcripts`
(`src/assistant/context.py`) attaches every screenshot within 60 s of any
retrieved transcript, carrying only `description` (usually NULL) and the file
path. `AssistantAnswerService._dict_to_context_prompt` then drops even the
description and prints `[Screenshot at <epoch>]: <filepath>`. The model
cannot tell what a screenshot contains, and it has no stable handle to cite
one by.
BU107 provides `search_session_screenshots`, which returns preview-tier cards
with the winners promoted to full metadata. Any Session mode uses a separate
path (router plus `rag_context_builder`) and its own `RESPONSE_CONTRACT`; it
must not change.

Tasks:
- `ScreenshotReference`: add `screenshot_id`, `preview`, `tier`,
  `ai_summary`, `visible_text`, `keywords`, and keep `filepath` for UI use.
  `to_prompt_text()` renders:
  - preview tier as one line: `[Screenshot #42 · 14:03:12] <preview>`;
  - full tier as a short block with Summary / Visible text / Keywords
    (already truncated by BU107 budgets).
  The file path is never rendered into the prompt.
- In `context.py`, replace `_get_screenshots_near_transcripts` with
  `search_session_screenshots(db, session_id, question,
  anchor_timestamps=[t.timestamp for t in transcripts])`, mapping hits to
  references.
- `tools._context_to_dict` carries the new fields.
  `service._dict_to_context_prompt` renders screenshots through the same
  format under `## Screenshots (index; full details only for the most
  relevant)`, and the epoch/filepath line is deleted. Keep one renderer,
  not two.
- New `src/assistant/screenshot_contract.py`:
  - `SCREENSHOT_CONTRACT`: appended to the system prompt only when
    `not is_any_session` and the context has at least one screenshot.
    Rules: screenshots are identified by `#ID`. When the answer relies on
    a listed screenshot, or the requested information is likely inside one,
    end with exactly one line `The information you asked might be contained
    in the screenshot: #<ID>` (comma-separated, max 3). Cite only IDs
    present in the context. When only a preview is available, say what is
    known and still point to it. Never invent on-screen content.
  - `parse_screenshot_refs(answer, allowed_ids) -> (clean_answer, ids)`:
    finds `#<digits>` on the final line(s) mentioning screenshot/captura, so
    a translated line still parses. IDs outside `allowed_ids` are dropped. If
    none survive, the line is removed from the answer.
- Service:
  - Track `self._last_screenshot_ids`, reset per request like
    `_last_routed_sessions`.
  - Add `AnswerResponse.screenshot_refs: List[int]`, default `[]`,
    populated in `_finalize_answer` for Specific Session only. The cleaned
    answer is what gets persisted.
  - Any Session messages and contract stay byte-for-byte unchanged.
