# BU121 — App Paths: Separate Install Folder From User Data

Status:
Completed

Goal:
Let the app run from any folder, including a read-only one like
`C:\Program Files\Chronicle`, by keeping everything it writes in a per-user
data folder and loading everything it ships from the install folder.

Context:
- Today everything is resolved against the project root or the working
  directory:
  - `chronicle.db`: relative path (`src/app/window.py:1018`,
    `src/storage/database.py:59`, `src/app/session_manager.py:125`).
  - `sessions/`: `project_root/sessions` (`src/app/window.py:712`,
    `session_manager.py:124`).
  - `preferences.json`: `project_root/preferences.json`
    (`src/app/window.py:1925`).
  - Icons: `src/app/pixel_theme.py:10-13` walks up from `__file__` to
    `assets/pixel`.
  - Models: the Hugging Face default cache (`~/.cache/huggingface`), used by
    both `onnx_asr.load_model` (`src/transcription/parakeet.py:192`) and
    `hf_hub_download` (`src/rag/embeddings.py:125`).
  - `.env`: `load_dotenv()` searches from the working directory.
- A relative `chronicle.db` means the database depends on where the app was
  started from. A shortcut with a different "Start in" folder silently opens
  or creates a different, empty database.
- Screenshot rows store **absolute** file paths (`screenshots.filepath`, e.g.
  `C:\Users\...\Chronicle-V2\sessions\session_062\...png`). This is fine as
  long as the data folder never moves after it is chosen. This BU does not
  move existing data.
- In a PyInstaller build, `__file__` points inside the bundle
  (`sys._MEIPASS` / `_internal`), so "project root" means nothing there.

Design:
- New module `src/paths.py`, the only place that knows about folders:
  - `resource_dir()`: the read-only files the app ships (`assets/`). This is
    the bundle folder when frozen (`getattr(sys, 'frozen', False)`), otherwise
    the project root.
  - `data_dir()`: the per-user writable root. Resolved in this order:
    1. the `CHRONICLE_DATA_DIR` environment variable (tests, power users);
    2. the location saved by the setup wizard (BU124) in a small pointer
       file, `%APPDATA%\Chronicle\location.json`;
    3. dev default: running from source (not frozen) keeps the project root,
       so the existing `chronicle.db`, `sessions/` and `preferences.json` are
       used unchanged;
    4. frozen default: `QStandardPaths.AppLocalDataLocation`
       (`%LOCALAPPDATA%\Chronicle`).
  - Derived: `db_path()`, `sessions_dir()`, `preferences_path()`,
    `models_dir()`, `logs_dir()`, all under `data_dir()`, created on first use.
- `models_dir()` is applied by setting `HF_HOME` in `main.py` **before** any
  `huggingface_hub` or `onnx_asr` import, so both model loaders share one
  cache inside the data folder.

Tasks:
- Add `src/paths.py` as designed above.
- Route the database, sessions folder, preferences file and icon lookups
  through it. Remove the three `project_root = dirname(dirname(dirname(...)))`
  computations.
- `Database` and `SessionManager` keep their path parameters, so tests still
  inject temp paths. Only the defaults change.
- `main.py` sets `HF_HOME` to `models_dir()` before importing the window.
  **Dev exception:** when running from source and the models already exist in
  the default Hugging Face cache, leave `HF_HOME` alone so nothing is
  downloaded again.
