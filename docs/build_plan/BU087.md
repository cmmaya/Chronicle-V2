# BU087 — Timestamp-Preserving Transcript Chunking

Status:
Completed

Goal:
Re-chunk session transcripts into time-windowed chunks that retain their own timestamp and source, so retrieved excerpts can be cited by `HH:MM:SS` and correlated with screenshots.

Context:
`index_session_content` (src/rag/indexer.py:72) concatenates every transcript row of a session into a single string, then splits it into 1000-char chunks. The resulting `rag_documents` row carries only the first transcript's timestamp, so individual chunks have no usable time anchor. This breaks the `HH:MM:SS` citation that the `chronicle_assistant` system instruction promises (src/config.py:13) and breaks `AssistantContextRetriever._get_screenshots_near_transcripts`, which matches screenshots to transcript timestamps within a 60-second window. Live data shows 836 transcripts collapsing into only 76 chunks. See docs/build_plan/ANY_SESSION_REFACTOR.md section 2.3.

Tasks:
- Replace whole-session concatenation with grouping of transcript rows into windows bounded by both elapsed time (target ~60 seconds) and size (target ~800 characters), whichever boundary is reached first.
- Give each chunk its own `timestamp` (the first transcript row in the window) and `source` (microphone / system), persisted per chunk rather than only on the parent document.
- Extend the `rag_chunks` schema with per-chunk `timestamp` and `source` columns if they are not already present, and carry them through `replace_rag_chunks` and `rebuild_rag_fts`.
- Keep summaries chunked as they are today; only transcript chunking changes.
- Update `AssistantContextRetriever._convert_rag_transcripts` (src/assistant/context.py:224) to read the per-chunk timestamp and source instead of inferring source from the document title.
- Preserve idempotency: re-indexing an unchanged session must not duplicate chunks (continue using the content hash).
- Provide a re-index path for already-indexed sessions so existing data picks up the new chunking.
