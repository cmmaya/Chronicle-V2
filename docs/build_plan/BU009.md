# BU009 — Implement Chunked Audio Recording

Status:
Pending

Goal:
Replace continuous recording with a chunked, rolling buffer mechanism for both microphone and system audio sources.

Context:
Chunking is critical for long-running sessions and for preserving temporal synchronization. Each chunk will be a discrete file with associated metadata, making the transcription and merging process more manageable.

Allowed Files:
- `src/audio_capture/core.py`
- `src/audio_capture/chunk.py` (new file)

Dependencies:
Required:
- BU008

Blocks:
- BU010

Tasks:
- Create a new `AudioChunk` data structure or class to hold the following metadata:
  - `source`: The origin of the audio (e.g., 'mic' or 'system').
  - `chunk_id`: A unique identifier for the chunk.
  - `timestamp_start`: The absolute start time of the chunk.
  - `timestamp_end`: The absolute end time of the chunk.
  - `file_path`: The path to the corresponding audio file.
- Modify the audio recorders to save audio in 10-second WAV chunks.
- Implement a naming convention for chunk files (e.g., `<timestamp_start>_<timestamp_end>.wav`).
- For each chunk created, save a corresponding metadata file (e.g., as JSON) or log the metadata to a central session database/file.

Out of Scope:
- Implementing the system audio capture logic.
- Processing these chunks in the transcriber.

Definition of Done:
[ ] Microphone audio is recorded and saved as a series of 10-second WAV files in the `.../audio/mic/` directory.
[ ] Each audio chunk has corresponding metadata that includes its source, start/end timestamps, and file path.
[ ] The architecture is ready to handle chunks from the system audio source in the same manner.

Reviewer Focus:
- Correct implementation of the 10-second chunking logic.
- Accuracy and completeness of the chunk metadata.
- Robustness of the recording loop for long-running sessions.
