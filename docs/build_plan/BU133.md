# BU133 — "Send To Calendar" Button And Event Dialog

Status:
Completed

Goal:
In the summary window, give each Due Dates entry its own **Send to Calendar**
button. The button opens a pixel-art dialog pre-filled with the entry's title,
description and date (time optional; no time means all-day). The user edits
it, then presses **Create Event** or **Discard**.

Context:
- `window.py` (~line 1640) builds the summary view: `parse_summary_sections`
  returns one `PixelCollapsibleSection(title, body)` per section, and the body
  is **one rich-text label** built by `format_summary_body_html`. Per-entry
  buttons do not fit in a single label, so the Due Dates section needs its own
  body widget with one card per entry.
- BU129: `parse_due_date_entries(body)` returns `DueDateEntry` objects with a
  parsed `date` / `start_time` / `end_time`, or `None`.
- BU131: `open_settings(page="Calendar")`. BU130: `connection_state()`.
  BU132: `EventDraft`, `create_event`, `event_exists` and the link table.
- `PixelWindowChrome` gives every `QDialog` the pixel title bar. The Settings
  pop-up (BU128) sets the look: a scrim, row cards and `PixelButton`s.

Tasks:
- `pixel_widgets.py`: a `PixelDueDateCard` for one entry, showing title, due
  text and description in the current style, with a button on the right
  aligned to the title.
  - Button states:
    - **Send to Calendar**: no link stored.
    - **✓ In Calendar**: a link is stored. Clicking offers "Open in Google
      Calendar" (the `htmlLink`) or "Send again…".
  - `PixelCollapsibleSection` accepts an optional body widget. `window.py`
    passes a column of `PixelDueDateCard`s for "Due Dates" when
    `parse_due_date_entries` returns at least one entry. Otherwise it keeps
    the current rich-text body (prose, or "No due dates were mentioned…").
  - The header count (the "2" badge) is unchanged.
- New `src/app/calendar_dialog.py`, `CalendarEventDialog(QDialog)`:
  - **Title**: a line edit, pre-filled with `entry.title`.
  - **Description**: a multi-line edit, pre-filled with `entry.description`
    plus a footer line: `From Chronicle session "<name>" (<recording date>)
    — due: <due_text>`. The due text keeps the spoken context ("or Friday",
    "15 minutes prior").
  - **Date**: a date picker. **All day** toggle (`PixelToggle`), on when
    `start_time` is `None`. When off, **Start** / **End** time edits appear
    (End defaults to Start + 1 h).
  - The date comes from `entry.date`. When it is `None` (unclear, recurring
    or two candidates), the date is empty and a gold hint shows: "The
    transcript didn't give a single date: '<due_text>'. Pick one."
  - A past date shows a warning ("This date is in the past"). It does not
    block.
  - Not connected: the dialog still opens so the user can review. The primary
    button reads **Connect Google…** and opens Settings › Calendar. When the
    user returns connected, it changes to **Create Event**.
  - **Create Event** is enabled only when `EventDraft.validate()` returns no
    errors. Errors show inline under the field.
  - Create runs `create_event` on a worker thread, and the buttons are
    disabled with "Creating…". On success: save the link, close, update the
    card to ✓ In Calendar, and show a status line with an "Open" link. On
    `GoogleAuthExpired`: "Your Google connection expired. Reconnect." plus
    the button to Settings. On `CalendarError` or no network: the dialog stays
    open with the message and keeps every edit.
  - **Discard** / Esc / ✕ close without creating anything. If fields were
    edited, ask "Discard your changes?".
- Re-sending (a link exists):
  - Check `event_exists` first.
  - If the event still exists, confirm: "This due date is already in your
    calendar. Create another event?"
  - If it was deleted in Google, drop the stale link and send it as a new
    event.
- Only one `CalendarEventDialog` is open at a time.

Validation Requirements:

Required:
- executable behavior verified
- no syntax/runtime errors
- Definition of Done satisfied
- manual validation:
  - Each Due Dates entry has its own button, and the section looks like the
    current design otherwise.
  - An entry with `Calendar date: <date>` opens with that date and All day on.
    Create puts an all-day event on the correct day.
  - An entry with a time opens with All day off and the times set. The event
    is created at the right local time.
  - "Thursday or Friday" and "15 min prior to each shift" open with an empty
    date and the hint, and Create stays disabled until a date is picked.
  - Editing the title, description or date changes the created event.
  - The card turns to ✓ In Calendar and stays that way after reopening the
    summary and after a restart. Send again asks first.
  - Delete the event in Google, then click Send again: no duplicate prompt,
    and a new event is created.
  - Not connected: Connect Google… → Settings › Calendar → after connecting,
    the dialog offers Create Event.
  - With no network, Create shows an error and every edit survives.
  - Discard after editing asks for confirmation. Discard without edits closes
    immediately.
  - Sessions without a Due Dates section, or with "No due dates were
    mentioned", show no buttons.

Out of Scope:

- Editing or deleting existing Google events from Chronicle
- Recurring events (entries like "before each shift" become single events the
  user picks a date for)
- Calendars other than primary
