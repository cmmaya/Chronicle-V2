# BU118 — Mic And System Audio Mute Toggles

Status:
Completed

Goal:
Let the user mute and unmute the microphone and the system audio independently
while a session is recording, from two icon toggles in the top-right corner of
the chat section, so a private aside or an unrelated video does not end up in
the transcript.

Context:
- Capture runs through `DualSourceChunkedRecorder`
  (`src/audio_capture/core.py:676`), which owns one `ChunkedAudioRecorder` per
  source (`mic`, `system`). Each recorder runs its own capture thread, feeds a
  chunk buffer, and emits chunks through the save and live-transcription
  callbacks.
- Mute must **not** stop or tear down a recorder. The watchdog
  (`_watchdog_loop`) restarts a recorder whose chunks stall, and
  `ChunkedAudioRecorder.stop()` flushes a final chunk and returns the chunk
  list — stopping a source to mute it would fight the watchdog, produce a
  spurious "audio lost" status, and end that source's recording for good.
  Mute is therefore a **drop gate**: the stream keeps running and keeps its
  device open, but captured audio is discarded before it becomes a chunk, so
  nothing is saved, nothing is transcribed, and nothing reaches the database.
- Muting must not look like a stall to the watchdog. A muted source produces no
  chunks by design, so `check_health` and the stall timer must treat a muted
  recorder as healthy rather than restarting it every
  `watchdog_stall_seconds`.
- The user supplied the four icons: mic-on, mic-off (slashed), speaker-on,
  speaker-off (slashed) — navy rounded square, cream glyph, matching the
  existing `assets/pixel/` vocabulary (`icon_play.svg`, `icon_pause.svg`).
  Top row is mic, bottom row is system audio; the un-slashed icon means the
  source is **active** (unmuted).
- The chat section is the center workspace, built in
  `MainWindow._build_center_workspace` (`src/app/window.py:2424`). Its top bar
  (`UnifiedSearchBar`) is centered with a max width; the two toggles go in the
  top-right of that header area, right-aligned, not inside the search frame.
- `PixelToolButton` (`src/app/pixel_widgets.py`) is the existing icon-button
  vocabulary and `MainWindow._make_icon` the existing loader — use both rather
  than a new widget class.
- Mute state is per-source and belongs to `SessionManager`, not to a session:
  the user asked to be able to silence a source *before* hitting record, so the
  choice has to outlive "there is no session yet" and be handed to each
  recorder as it is built. It stays in memory only - persisting it across app
  restarts is out of scope.

Tasks:
- `ChunkedAudioRecorder` (`src/audio_capture/core.py`):
  - Add a thread-safe muted flag with `set_muted(bool)` and an `is_muted`
    property. Default unmuted.
  - Gate audio at ingest: while muted, captured blocks are dropped instead of
    fed to the chunk buffer, for both the sounddevice callback path
    (`_recording_loop`) and the system loopback path
    (`_system_recording_loop`). No chunk is saved, no callback fires, no live
    transcription runs.
  - Unmuting must not splice pre-mute and post-mute audio into one chunk:
    clear or flush pending buffered audio on the mute transition so the first
    chunk after unmute starts clean and its timestamp is honest.
  - Muting mid-chunk must not emit a partially-silent chunk that then gets
    transcribed — document in a comment which of the two (drop the partial or
    flush it) was chosen and why.
  - `check_health` reports a muted recorder as healthy, with a reason string
    saying it is muted, so the watchdog leaves it alone.
- `DualSourceChunkedRecorder`:
  - `set_source_muted(source, muted)` and `is_source_muted(source)` for
    `'mic'` and `'system'`, raising on an unknown source.
  - A restart (watchdog or manual) preserves the source's mute state.
- Session plumbing:
  - `src/app/session.py` and `src/app/session_manager.py` expose setting and
    reading mute per source on the active session, and no-op safely (with a
    return value the UI can act on) when no session is recording or the dual
    recorder does not exist yet.
  - Mute set before recording starts applies once the recorder is created.
- Icons: add the four SVGs to `assets/pixel/` following the existing naming —
  `icon_mic_on.svg`, `icon_mic_off.svg`, `icon_audio_on.svg`,
  `icon_audio_off.svg`.
- UI in `_build_center_workspace`:
  - Two `PixelToolButton` toggles, right-aligned in the top-right of the chat
    section's header row, mic first and system audio second, consistent with
    the existing 28 px icon sizing.
  - Each swaps its icon on toggle (un-slashed = active, slashed = muted) and
    carries a tooltip naming both the source and the action
    ("Mute microphone" / "Unmute microphone").
  - The toggles are clickable at all times, including before any session
    exists; a click with no session is remembered and reported as such
    ("(applies when recording starts)"). The displayed state is always the
    state capture will use, so it is never silently reset.
  - Toggling reports through the existing status path so the user gets a
    confirmation line ("Microphone muted").
- Config: a `MUTE` block in `src/config.py` only if a value is genuinely
  needed (for example whether a muted source is still watchdog-probed). Do not
  add settings nothing reads.

Validation Requirements:

Required:
- executable behavior verified
- no syntax/runtime errors
- Definition of Done satisfied
- manual validation:
  - Start a session, mute the mic, speak, and confirm nothing from the mic
    appears in the live transcript while system audio keeps transcribing.
  - Unmute and confirm mic transcription resumes within one chunk.
  - Mute system audio with media playing and confirm the same, in reverse.
  - Mute both for longer than `watchdog_stall_seconds` and confirm no "audio
    lost" status and no watchdog restart.
  - Stop the session and confirm the saved audio and stored transcript contain
    no muted-period audio for the muted source.
  - Mute the mic with no session running, then start one, and confirm the mic
    is muted from the first chunk.

Tests Required:
- yes — `set_muted` / `is_muted` defaults and toggling, that a muted recorder
  drops audio (no chunk saved, no save callback, no live-transcription
  callback), that unmuting resumes chunking and does not splice pre-mute audio,
  that `check_health` reports a muted recorder healthy, `set_source_muted` per
  source and its unknown-source error, that mute state survives a restart, that
  a mute chosen with no session reaches the recorder built later, and that the
  session-level setter no-ops without a recorder

Out of Scope:
- Persisting mute state in `preferences.json` or across app restarts (superseded by BU119, which persists it)
- A global mute hotkey
- Muting playback, or muting the OS-level device
- Per-device selection, gain, or input-level metering
- Any change to pause/resume session lifecycle
- Marking muted spans in the transcript or timeline
