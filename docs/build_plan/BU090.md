# BU090 — Assistant Answer Contract And Scope Handoff

Status:
Completed

Goal:
Have the assistant classify its own answer's intent and evidence quality inside the same call that produces the answer, and use that signal to tell the user when Any Session cannot reach transcript-level detail, pointing them at the specific session to ask instead.

Context:
In Any Session mode the assistant only ever sees session-level material — summaries and bounded excerpts — but it answers detail questions as though it had the full transcript. A separate classifier call would double latency and cost. Instead the model returns the answer plus a metadata trailer in one response; the app strips the trailer before anything is displayed or stored, and uses it to decide whether to offer the handoff. The candidate-session picker needed for that handoff already exists for the ambiguity flow (`_display_candidates` src/app/window.py:4848, `_on_use_candidate_clicked` src/app/window.py:4898, which already re-runs the question with `current_session` scope and the chosen session id) and must be reused rather than rebuilt. See docs/build_plan/ANY_SESSION_REFACTOR.md sections 3.2, 3.3 and 2.6.

Tasks:
- Add `src/assistant/response_contract.py` holding the contract prompt text and a pure `parse_answer(raw) -> ParsedAnswer` with fields `answer_text`, `intent`, `evidence`, `sessions`.
- Parse by splitting on the last occurrence of the `@@CHRONICLE_META@@` sentinel; `answer_text` is everything before it, right-stripped; the metadata is the first `{` through the last `}` of the remainder, parsed with `json.loads`.
- Any parse failure, missing sentinel, or unrecognised enum value must yield `answer_text` equal to the full raw response with `intent=None`, `evidence=None`, `sessions=[]`. The parser must never raise.
- Append the response contract to the system prompt in Any Session mode only. Leave Specific Session prompts untouched.
- Add `ANY_SESSION_TEMPERATURE = 0.2` to src/config.py and use it for the Any Session call so contract compliance is reliable. Leave `OpenRouterClient.DEFAULT_TEMPERATURE` (0.7) and every other call path unchanged. The value is a named constant so it can be tuned without hunting through code.
- If the trailer is missing or malformed in more than roughly 5% of responses across the models actually in use, lower the constant to 0.1. Do not set it to 0.0; some models in `ALLOWED_MODELS` degenerate into repetition there. Temperature reduces how often the parser fallback fires; it is not the safety net.
- Strip the metadata trailer before `_persist_conversation` (src/assistant/service.py:553) so the sentinel never re-enters the prompt as conversation history on later turns.
- Extend `AnswerResponse` with optional `intent`, `evidence`, `scope_used` and `candidate_sessions` fields, all defaulted so existing consumers and tests are unaffected.
- Populate `candidate_sessions` from the BU089 router results when the scope is Any Session.
- In the UI, when the scope is Any Session and `intent == "detail"` or `evidence` is `partial` or `none`, append a short handoff note to the answer and show the existing candidate picker seeded with the routed sessions, with the group title and button relabelled toward asking in Specific Session.
- Never render `intent` or `evidence`. Log them only.
- Apply the same handoff behaviour in the detached assistant window using `_display_detached_candidates` (src/app/window.py:5389).
- Request the trailer on every Any Session turn, not only the first.
