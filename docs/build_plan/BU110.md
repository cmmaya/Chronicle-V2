# BU110 — Screenshot Extras: Visible-Text Search, Live-Session Viewing, Capture Hotkey

Status:
Completed

Goal:
Add three user-requested extras on top of the BU109 viewer:
1. search screenshots by their visible text;
2. view (and keep receiving) screenshots while a session is active;
3. capture a screenshot with a keyboard shortcut from any app.

Context:
- Visible-text search: `visible_text` is a JSON list written by the vision
  model (BU106), present only for screenshots that have AI context. Nothing
  currently searches it.
- Live viewing: the BU109 viewer opens modally (`exec()`) and holds a
  snapshot of the rows. A screenshot taken while it is open never shows up,
  and the modal dialog blocks the main window (pause, stop, assistant)
  during a live session. `_on_take_screenshot` minimizes only the main
  window before the snip overlay, so an open viewer would end up inside the
  capture.
- Hotkey: `ScreenshotCapture.register_shortcuts` (Ctrl+Shift+S /
  Ctrl+Shift+R, window-local) is never called. Capture is only reachable
  through `screenshot_icon_button`, with Chronicle focused.
- Win+Shift+S is reserved by Windows (Snipping Tool, owned by the shell).
  `RegisterHotKey` fails for it, and intercepting it with a low-level
  keyboard hook would break the OS tool. So the plan is:
  - a configurable system-wide hotkey, default Ctrl+Alt+S;
  - an opt-in mode that imports images the native Win+Shift+S puts on the
    clipboard.

Tasks:
A. Visible-text search
- Add a search field to the viewer header (Ctrl+F focuses it, Esc clears it).
  Matching is accent- and case-insensitive against `visible_text` items. An
  "Also description & summary" toggle extends the match to `description`,
  `preview_description` and `ai_summary`.
- The filmstrip filters to matches and shows "N matches". Enter / F3 goes
  to the next match. Matching lines in the Visible Text section are
  highlighted.
- Scope toggle "This session | All sessions". All sessions calls
  `Database.search_screenshots_text(query, session_id=None,
  include_context=False, limit=200)`: a SQL `LIKE` prefilter, then accent
  normalization in Python. Results are labelled by session name, and
  selecting one shows it in the stage with its session in the header.
- Hint row when some screenshots in scope have no visible text: "4
  screenshots have no visible text yet: Generate missing" (triggers the
  BU109 action for the current session).

B. Live-session viewing
- Make the viewer non-modal (`show()`) with one instance per session: reopening
  focuses the existing window. The main window stays usable.
- Opening the viewer for the live session (active or paused) works from the
  icon button and from the All Sessions "View screenshots" menu item.
- Live refresh: every successful capture (icon button, hotkey, clipboard
  import) emits `screenshot_captured(session_id, screenshot_id)`. An open
  viewer for that session appends the new thumbnail, and jumps to it if the
  user was on the last item.
- Hide open viewers before the snip overlay and restore them afterwards,
  alongside the main window.
- Context generation during a live session runs on the existing background
  thread without touching recording (no summary needed, per BU109).

C. Capture hotkey
- Create `src/app/global_hotkey.py`: Win32 `RegisterHotKey` /
  `UnregisterHotKey` via `ctypes`, plus a `QAbstractNativeEventFilter`
  catching `WM_HOTKEY` and emitting a Qt signal. No new dependency. It is a
  no-op on non-Windows platforms. Includes a pure parser from a key string
  ("Ctrl+Alt+S") to `(modifiers, vk)`.
- Config: `SCREENSHOT = {"global_hotkey": "Ctrl+Alt+S",
  "import_clipboard_snips": False}` in `src/config.py`.
- Register the hotkey only while a session is live (start / resume) and
  unregister it on stop and on app exit, so the key isn't held otherwise.
  If registration fails (combo already taken), show a status-bar message
  and fall back to a window-local `QShortcut`.
- The hotkey runs the same path as the icon button: hide windows, snip
  overlay, description prompt, store, timeline, live refresh.
- Opt-in Win+Shift+S support: while a session is live and
  `import_clipboard_snips` is on, a `QClipboard.dataChanged` event carrying
  an image is saved as a session screenshot via a new
  `ScreenshotCapture.import_image(image, session_name, session_id)` reached
  through `SessionManager.import_clipboard_screenshot`. Repeat events for the
  same image hash within 5 s are ignored, and the status shows "Screenshot
  imported from clipboard". It is off by default because any copied image
  would be captured.
- Remove the dead `ScreenshotCapture.register_shortcuts`.
