# BU167 — Diarization Progress Bar On The Session Card

Status:
Completed

Goal:
While a session is being diarized, its card in the All Sessions window
shows a loading bar with the current step, in every appearance.

Context:
- Cards are rebuilt on every list reload; busy chips already survive that
  through `state['busy']` in `_show_all_sessions_window`. The bar must too.
- The window's bottom progress bar belongs to uploads. Diarization is per
  session and long, so its bar lives on the session's own card.
- BU165 reports real progress (percent + stage text), so the bar is
  determinate.

- src/app/pixel_widgets.py (`PixelSessionCard`, new `PixelCardProgress`)
- src/app/window.py (All Sessions window wiring)
- src/app/theme.py (progress tokens per appearance)

- tests/test_bu167.py (new)
- docs/build_plan/BU167.md

Tasks:
- `PixelCardProgress`: a strip under the card's meta line, full text
  width. Stage text on the left ("Downloading models…", "Finding
  speakers…", "Transcribing speakers 12/57…"), percent on the right, the
  bar below. Hidden when idle; the card grows to fit it while shown.
- Per appearance:
  - Classic: pixel-cut 6 px bar, navy track, orange chunk, Courier text
  - Synthwave: same shape, the theme's neon remap of the chunk with a
    soft glow on its leading edge
  - Boring Corporate: 4 px rounded track on the grey surface, white chunk,
    Segoe UI sentence-case text
- The bar eases toward each new value (no jumps); at 100% it holds for
  350 ms, then the strip hides.
- Progress lives in the window state (like `busy`), so a reload, a filter
  change or reopening the window brings the bar back where it was.
- A "Speakers" chip (icon + count, like the documents chip) on cards with
  diarization enabled; after a failed run the chip shows an error state
  with the reason in its tooltip.
