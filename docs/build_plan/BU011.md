# BU011 — Refactor Transcriber for Chunk-Based Processing

Status:
Pending

Goal:
Modify the `transcriber` module to process individual audio chunks from multiple sources instead of a single continuous audio file.

Context:
With audio now arriving in chunks, the transcriber needs to be adapted to handle this new input format. It will process chunks from both the microphone and system audio directories independently, preserving the source of each transcription.

Allowed Files:
- `src/transcriber/core.py`
- `src/session/manager.py`

Dependencies:
Required:
- BU010

Blocks:
- BU012

Tasks:
- Modify `TranscriptionProcessor` to poll the `mic` and `system` audio directories for new chunks.
- Update the transcription logic to process one chunk at a time.
- The output of the transcription for each chunk must be stored in a way that preserves the original audio chunk's metadata (especially `source` and `timestamp_start`). This could be a new table in the database or structured files.
- Update `SessionManager` to trigger this new chunk-based transcription process.

Out of Scope:
- Merging or ordering the final transcripts.
- Displaying the transcript in the UI.

Definition of Done:
[ ] The transcriber processes `.wav` files from both `.../audio/mic/` and `.../audio/system/` directories as they appear.
[ ] The resulting transcript for each chunk is stored along with its source ('mic' or 'system') and start timestamp.
[ ] The system can handle a continuous stream of new audio chunks for transcription.

Reviewer Focus:
- The transcriber correctly processes chunks from both sources.
- Source attribution and timestamps are preserved in the transcription output.
- The polling mechanism is efficient and reliable.
