# BU134 — Session Origin Flag For Inserted Transcripts

Status:
Completed

Goal:
Persist, per session, whether its transcript came from audio or was inserted
from a text file, so every later layer (import, summary, UI) can branch on a
single flag.

Context:
- `sessions` has no notion of where a transcript came from. Recorded and
  uploaded-audio sessions both have `transcripts` rows with
  `source = 'microphone' | 'system'`.
- The user wants a text upload that becomes a session whose transcript "has a
  flag" and renders differently.
- `database.py` versions its schema: `SCHEMA_VERSION = 3`, and
  `_migrate()` adds columns with `_add_column` (idempotent) per version step.
  `list_sessions_with_flags` selects `s.*`, so a new column flows to the All
  Sessions window without query changes.

Decisions:
- New column `sessions.origin TEXT NOT NULL DEFAULT 'recorded'`. Values:
  `'recorded'` (default, every existing row), `'text'` (inserted transcript).
  Uploaded-audio sessions stay `'recorded'`: they behave like recordings.
- Inserted transcript rows use `transcripts.source = 'inserted'`. The session
  flag is the source of truth; the row source keeps search/RAG/assistant
  output from mislabelling the text as "System".
- Module constants in `database.py`: `SESSION_ORIGIN_RECORDED = 'recorded'`,
  `SESSION_ORIGIN_TEXT = 'text'`, `TRANSCRIPT_SOURCE_INSERTED = 'inserted'`.
