# BU132 — Calendar Event Service And Sent-Event Tracking

Status:
Completed

Goal:
A small service that turns an edited due date (title, description, date,
optional time) into a Google Calendar event on the connected account. It also
records which summary entry produced which event, so the UI can show "In
Calendar" and warn before creating a duplicate.

Context:
- BU130 provides `get_access_token()`, which raises `GoogleAuthExpired` when
  access was revoked.
- Calendar API v3 `events.insert` (`POST
  /calendar/v3/calendars/primary/events`):
  - All-day events use `start.date` / `end.date`. `end.date` is **exclusive**,
    so a single-day event ends on the next day.
  - Timed events use `start.dateTime` / `end.dateTime` (RFC 3339 with offset)
    plus `timeZone`.
  - The response has `id` and `htmlLink`.
- The user's rule: no time given → an all-day event.
- `database.py` creates its tables with `CREATE TABLE IF NOT EXISTS` in one
  schema block. `summaries` rows are replaced when a session is re-summarized,
  so a link keyed on `summary_id` would be lost on regeneration.

Decisions:
- Timed event with no end time → 1 hour long. (The user can change it in the
  dialog.)
- Time zone: the machine's local zone. The IANA name comes from
  `tzlocal`-free logic: `datetime.now().astimezone()` for the offset, and
  `timeZone` is omitted when no IANA name is available (Google then uses the
  offset).
- Reminders: the calendar's defaults (`reminders.useDefault = true`).
- Duplicate key: `(session_id, fingerprint)`. The fingerprint is a SHA-1 of
  the normalized title (lowercase, collapsed whitespace, no punctuation). It
  survives re-summarization when the title stays the same.
- Every event gets `extendedProperties.private.chronicle_session_id` and
  `chronicle_fingerprint`. The link can then be rebuilt later if the local DB
  is lost. (Rebuilding is out of scope here.)

Tasks:
- `src/calendar_sync/events.py`:
  - `EventDraft` dataclass: `title`, `description`, `date`,
    `start_time: Optional[time]`, `end_time: Optional[time]`.
    - `validate() -> list[str]` returns messages for: an empty title, a
      missing date, `end_time` set without `start_time`, `end <= start`, a
      title over 1,024 characters, and a description over 8,000 characters.
    - `to_event_body(session_id, fingerprint)` builds the all-day or timed
      body as described above.
  - `create_event(draft, session_id, fingerprint) -> CreatedEvent(id,
    html_link)`:
    - 401 once → refresh the token and retry once.
    - 403 / `insufficientPermissions` → `GoogleAuthExpired`.
    - Other errors raise `CalendarError` with a short, readable message and a
      10 s timeout. Log without the event body.
  - `event_exists(event_id) -> bool` (`GET`; 404 or `status=cancelled` →
    False). Used before re-sending.
- `database.py`:
  - New table `calendar_events(id INTEGER PRIMARY KEY, session_id INTEGER
    NOT NULL, fingerprint TEXT NOT NULL, google_event_id TEXT NOT NULL,
    html_link TEXT, event_date TEXT, created_at REAL, UNIQUE(session_id,
    fingerprint))`, with `ON DELETE CASCADE` from `sessions`.
  - `get_calendar_link(session_id, fingerprint)`,
    `save_calendar_link(...)` (upsert) and `delete_calendar_link(...)`.
- `due_dates.py`: `DueDateEntry.fingerprint` uses the normalization above.

Validation Requirements:

Required:
- executable behavior verified
- no syntax/runtime errors
- Definition of Done satisfied
- manual validation (real account, from a Python shell):
  - An all-day draft for 2026-09-24 appears in Google Calendar on the 24th
    only, as an all-day event.
  - A draft at 15:00 with no end appears 15:00–16:00 local time.
  - A draft at 15:00–15:30 appears with exactly that span.
  - The link is stored. Deleting the event in Google makes
    `event_exists` return False.
  - Deleting the Chronicle session removes its `calendar_events` rows.

Tests Required:
- yes: `tests/test_bu132.py` (HTTP mocked):
  - `validate()` covers each rule
  - the all-day body has `date` fields with an exclusive end (+1 day),
    including a month or year boundary (2026-12-31 → 2027-01-01)
  - the timed body has a 1 h default, an explicit end and a local offset
  - the extended properties carry the session ID and fingerprint
  - a 401 retries once after a refresh, and a second 401 raises
  - the fingerprint is stable across case, spacing and punctuation changes
  - the link upsert and lookup work, and deleting a session cascades

- Rebuilding links from extended properties
