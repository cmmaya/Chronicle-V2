# BU104 — Upload Audio File As Session

Status:
Completed

Goal:
Let the user upload a WAV file or an iPhone recording (Voice Memos `.m4a`)
from the All Sessions window as a new session, transcribed with the existing
batch pipeline. An "Upload Audio" button sits in the window's bottom bar,
left of Close, replacing the Refresh button.

Context:
The user wants to bring in meetings recorded away from the PC - typically
with iPhone Voice Memos, which saves `.m4a` (AAC, or Apple Lossless when
"Lossless" is on). Until now a session could only be created by recording
live. The batch pipeline (`TranscriptionProcessor.process_all`) already
transcribes any session whose `audio/mic/*.wav` chunks carry the live
recorder's `YYYYMMDD_HHMMSS_YYYYMMDD_HHMMSS` naming, so an upload only has to
land its audio in that shape. The Refresh button is redundant: the dialog is
modal and already reloads itself after every action and whenever recording
starts, stops, pauses or resumes.

Tasks:
- New `src/audio/importer.py`:
  - `decode_audio_file(path)`: decode the first audio track with PyAV
    (FFmpeg) and resample to 16 kHz mono int16 (Parakeet's native rate);
    also return the recording time from the container's `creation_time`
    metadata when present. FFmpeg errors surface as a readable `ValueError`.
  - `split_at_pauses(samples)`: ~30 s chunk ranges, each cut at the quietest
    50 ms of its final 5 s so a word is never split; the last chunk absorbs
    the remainder (never a sliver).
  - `write_chunks(samples, audio_dir, start_time)`: write the chunks as
    PCM_16 WAVs named `<start>_<end>_import.wav`.
- `SessionManager.import_audio_file(file_path)`: decode first (nothing is
  created for an unreadable file), then create a `stopped` session named
  after the file stem, with start_time = embedded creation time or the file's
  modified time minus its duration, and end_time = start + duration. Write
  the chunks into `audio/mic`; roll back the DB row and folder if writing
  fails. Return the Session with its transcription processor attached.
- `TranscriptionProcessor._transcribe_and_store`: skip the cross-chunk dedup
  for `_import` chunks - they don't overlap, and its fuzzy matcher deletes
  any 2+ word phrase repeated from the previous chunk.
- All Sessions window (`_show_all_sessions_window`): remove the Refresh
  button; add an "Upload Audio" `PixelButton` left of Close, wired to
  `_upload_audio_from_all_sessions(dialog)`:
  - file picker filtered to the supported extensions, opening in the last
    used folder, else Downloads;
  - import under a wait cursor + status message; an error message box on
    failure;
  - reset search / filter, reload, select and scroll to the new card
    (`dialog._focus_session`), set its Transcript chip to busy;
  - `_transcribe_uploaded_session` runs `SessionManager.process_transcriptions`
    (sets `transcription_status`, RAG-indexes); on failure the session stays
    as "Needs transcript" so "•••" → Transcribe can retry it.
- `requirements.txt`: add `av` (PyAV; wheels bundle FFmpeg, no system
  install).

Validation results:
- `python -m py_compile` on all four changed source files -> OK; `import
  src.app.window` -> OK.
- Fixtures: ~68 s of TTS speech as WAV (22 kHz), AAC `.m4a` (48 kHz, with
  `creation_time`, as Voice Memos writes) and stereo Apple Lossless `.m4a`.
  All three decode to the same 67.8 s, split into 27.9 / 25.7 / 14.3 s
  chunks cut in true silence, and import as 16 kHz mono PCM_16 chunks. The
  AAC session is dated from its metadata; the others from mtime - duration.
- A non-audio `.m4a` raises "isn't an audio file Chronicle can read" and
  leaves no DB row or folder behind.
- Real Parakeet transcription of the imported AAC session: 3 timestamped
  transcripts matching the script, `transcription_status=transcribed`, RAG
  indexed. Stored text equals the model's raw output; the old dedup path
  would have deleted words from chunks 2 and 3.
- Headless UI run (offscreen Qt, temp DB): bottom bar is exactly
  [Upload Audio] [Close]; upload selects the new card, shows "Transcribing",
  then "✓ Transcript"; an upload dated in the past is scrolled into view
  under its own day group; a simulated transcription failure shows the
  message box and leaves the card as pending.
- Existing suite (hardware / network tests excluded): 366 passed; 18
  failures in `test_assistant_service.py` / `test_openrouter_client.py` are
  HTTP 401s from live OpenRouter calls, unrelated to this BU.
