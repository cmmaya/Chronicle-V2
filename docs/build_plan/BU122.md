# BU122 — API Key In The Windows Credential Store

Status:
Completed

Goal:
Store the OpenRouter key in one secure place, read it the same way
everywhere, and let the user set, test and change it from inside the app.

Context:
- The key is read in two places, each with its own copy of the logic:
  `src/assistant/openrouter_client.py:58-64` and
  `src/summarization/generator.py:81-89`. Both call `load_dotenv()` and then
  `os.getenv("OPENROUTER_API_KEY")`.
- An installed app has no `.env` file. A plain-text key in the data folder
  would be readable by anything running as that user and would end up in
  backups.
- `keyring` stores secrets in the Windows Credential Manager, encrypted per
  user by the operating system. It is pure Python and packages cleanly.
- The key is the user's own. The app must never ship with a key.

Tasks:
- `src/secrets.py`:
  - `get_api_key() -> str | None`: the `OPENROUTER_API_KEY` environment
    variable or `.env` first (keeps dev and CI working), then `keyring`
    (service `Chronicle`, user `openrouter`).
  - `set_api_key(key)` and `clear_api_key()` (keyring only).
  - `check_api_key(key) -> (ok, message)`: one cheap authenticated call to
    OpenRouter's key-info endpoint (`GET /api/v1/key`, no tokens spent) with a
    short timeout. The message is human-readable: invalid key (401), no
    credits (402), offline or timeout, or OK.
- Both clients call `get_api_key()`. The error when it is missing says to set
  the key in Settings, not to set an environment variable.
- In the existing Model Settings dialog (or a new "API Key" entry in the same
  menu): a masked field showing only the last 4 characters, plus Test, Save
  and Remove buttons.
- Add `keyring` to `requirements.txt`.
- Never log the key. Redact it in any exception text that could contain the
  request headers.
