# BU141 — Live-Aware Transcript Retrieval

Status:
Completed

Goal:
Specific Session questions asked while a session is recording, or before its RAG index catches up after Stop, get real transcript evidence instead of the 5-row keyword fallback.

Context:
- RAG indexing (`index_session_content`) only runs after Stop / finalize / summarize, so a live session has no index and every chat question fell back to `_get_transcripts`: 5 raw rows (~80 chars each) ranked by substring keyword count.
- Observed 2026-10-07: session 81 stopped 21:50:42, question asked 21:51:42, transcript indexed 21:51:52. The model got 5 unrelated lines and answered "no mention of an assignment".
- Re-indexing during recording is too costly: the transcript is one RAG document, so every new row changes its hash and re-embeds every chunk.

Tasks:
- `build_session_context` loads the raw rows once; the session is "live" when its status is `active`/`paused`, and "indexed" when not live and the transcript RAG document's `transcript_count` covers every row (`_index_covers`; a db that cannot answer is trusted).
- Live or unindexed: `_get_transcripts` builds the indexer's time windows in memory (`_chunk_transcripts`), keeps up to 12 matching windows plus the newest windows up to `RECENT_TAIL_CHARS` (3000), returned in time order. It also replaces the old 5-row fallback when the index finds nothing.
- Excerpts are cut once, at `MAX_TRANSCRIPT_LENGTH` = 900 (windows are <= 800).
- `AssistantContext` gains `transcript_live`, `transcript_indexed`, `transcript_until`; `tools._context_to_dict` passes them as `transcript_state`.
