# BU107 — Two-Tier Screenshot Search Engine

Status:
Completed

Goal:
Build a pure retrieval engine that, for a question about one session, ranks
that session's screenshots using only their Tier-1 preliminary metadata, then
loads full metadata only for the few that win.

Context:
BU106 gives every screenshot a short preview (`preview_description`) plus
`keywords`, readable through `get_screenshot_previews(session_id)` without
touching the heavier `ai_summary` / `visible_text` fields. A session has tens
of screenshots, not thousands, so an in-memory scorer per session is enough.
No FTS table is needed: the RAG indexer does not index screenshots, and
`SourceType.SCREENSHOT` is currently unused.
Transcript chunks retrieved for the question (time-windowed since BU087) also
give a useful time signal: a screenshot taken while the relevant topic was
being discussed is likely relevant even when its preview doesn't share words
with the question. Users mix Spanish and English, so matching must ignore
accents and handle stop words in both languages.

Tasks:
- Add `Database.get_screenshot_details(ids)`: one `WHERE id IN (...)` query
  returning `id`, `timestamp`, `filepath`, `description`, `ai_summary`,
  `visible_text`, `keywords`.
- Create `src/screenshots/search.py` (no Qt, no network). Budget constants
  go at the top: `MAX_PREVIEW_CARDS = 12`, `MAX_FULL_DETAILS = 3`,
  `PREVIEW_CHARS = 240`, `DETAIL_CHARS = 900`.
- `ScreenshotHit` dataclass: `screenshot_id`, `timestamp`, `filepath`,
  `preview`, `score`, `reasons` (subset of `lexical`, `temporal`,
  `reference`), `tier` (`preview` | `full`), `details` (optional dict with
  `ai_summary`, `visible_text: list`, `keywords: list`, `description`).
- `normalize_tokens(text)`: lowercase, accent-fold (NFKD), drop English and
  Spanish stop words, keep tokens of 3+ chars, trim simple plurals.
- Tier 1 `rank_previews(previews, question, anchor_timestamps)`:
  - lexical: weighted token overlap of the question with preview and
    description (weight 1.0) and keywords (weight 1.5);
  - temporal: 1.0 when within 60 s of any anchor timestamp, decaying
    linearly to 0 at 180 s;
  - explicit reference: "screenshot #42", "screenshot 42", "captura 42"
    forces that ID to the top;
  - deictic fallback: questions like "what was on screen", "in the
    screenshot", "la captura" with no lexical hit boost the screenshot
    nearest to the anchors, or else the most recent one;
  - stable ordering by score, then timestamp.
- Tier 2 `promote(hits, db, max_full=MAX_FULL_DETAILS, min_score=...)`: fetch
  full metadata only for the top hits above the threshold, with a single
  `get_screenshot_details` call. Parse the JSON fields safely and truncate
  them to `DETAIL_CHARS`.
- Entry point `search_session_screenshots(db, session_id, question,
  anchor_timestamps=(), max_preview=MAX_PREVIEW_CARDS, max_full=MAX_FULL_DETAILS)
  -> list[ScreenshotHit]`: calls BU106 `ensure_previews` first, then returns
  up to `max_preview` cards (relevant ones first, then the most recent) with
  the promoted ones marked `tier='full'`.
