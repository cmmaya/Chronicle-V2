# BU111 — Structured Transcript Records And Detached Bubble Grouping

Status:
Pending

Goal:
Give the detached transcripts window the same grouped bubbles the main panel
has, backed by structured transcript records instead of pre-formatted
strings, so later BUs can select, detect on, and answer individual chunks.

Context:
- `MainWindow._transcription_history` is a list of display strings
  (`"[HH:MM:SS] Mic: text"`). `_add_transcription_to_detached` re-parses each
  one with a regex to recover source and time. Start/end datetimes and the
  `transcripts.id` row are lost, so nothing downstream can map a bubble back
  to a chunk.
- The main panel groups chunks into one bubble via `add_transcription_to_view`
  and `self._transcript_groups`: consecutive same-source chunks extend the open
  bubble while `gap <= TRANSCRIPT_PAUSE_GAP_SECONDS` (7.5 s) and
  `duration <= TRANSCRIPT_MAX_GROUP_SECONDS` (60 s). The detached window does
  **not** do this - `_on_live_transcription` comments it as "kept flat
  per-chunk (out of scope)". The user requires the 60 s grouping in the
  detached window, so this is new behavior there, not a no-op.
- `add_transcription_to_view` ends with a dead `if ... self._detached_display:
  pass` block left from an earlier design.
- Both live arrival (`_on_live_transcription`) and past-session replay
  (`_load_transcripts_for_session`) must produce the same records, so a
  reopened session renders identically to a live one.

Tasks:
- Add a `TranscriptRecord` dataclass in `src/app/window.py`: `text`,
  `source` ('mic'|'system'), `start_dt`, `end_dt`, `transcript_id`
  (Optional[int]), `display_text`. Keep `display_text` so the BU101 download
  and existing find/filter paths are untouched.
- Replace `self._transcription_history: list[str]` with
  `self._transcript_records: list[TranscriptRecord]`. Keep a
  `_transcription_history` property returning `[r.display_text for r in ...]`
  so BU101 download and any other string consumer keeps working unchanged.
- Populate records from both producers:
  - `_on_live_transcription` (has `timestamp_start` / `timestamp_end` ISO
    strings already);
  - `_load_transcripts_for_session` (has `timestamp`; derive `end_dt` with
    `ChunkedAudioRecorder.CHUNK_DURATION` as it does now, and carry the row
    `id` into `transcript_id`).
- Extract the grouping decision from `add_transcription_to_view` into a pure
  helper `should_extend_group(group, start_dt, end_dt) -> bool` so both panels
  and the tests use one rule. Behavior must stay identical to today's inline
  check.
- Rewrite `_add_transcription_to_detached` to take a `TranscriptRecord` and
  apply the same grouping as the main panel, using its own
  `self._detached_transcript_groups` dict (the two panels must not share
  group state - one may be filtered while the other is not).
- Store each bubble row's originating record indices in a row property
  (`record_indices`, a list) so BU113 can map a clicked bubble back to the
  chunks it contains. A grouped bubble accumulates indices as it extends.
- Keep `find_text` / `source` row properties and the existing filter behavior
  working for grouped detached bubbles.
- Remove the dead `if hasattr(self, '_detached_display') ... pass` tail in
  `add_transcription_to_view`.
