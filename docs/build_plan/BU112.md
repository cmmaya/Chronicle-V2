# BU112 — Detached Window Two-Column Layout And Transcript Polish

Status:
Pending

Goal:
Restructure the detached transcripts window into two columns - answers on the
left, transcripts on the right - and make the transcript stream itself read
smoothly, since this window doubles as the transcript viewer.

Context:
- `_on_detach_transcription` currently builds a single-column window: a top
  row with the filter icon, a "TRANSCRIPTIONS WINDOW" section title, and one
  `PixelPanel(inner=True)` wrapping a `QScrollArea`.
- The user requires transcripts right / answers left. The left column has no
  content until BU113 and BU115, so this BU builds it as an empty rail with a
  proper empty state rather than leaving dead space.
- The window is the user's main way to read a transcript, so scroll and
  rendering quality matter as much as the new column.
- Existing theme vocabulary to reuse: `PixelPanel`, `PixelSectionTitle`,
  `PixelToolButton`, `pixel_filter_chip`, `PixelBubble`, the `#071D52` /
  `#3E6B9B` palette, and the `_make_icon` SVG loader.
- BU105 reworked threading/memory; a long session can hold hundreds of bubble
  widgets, so scrolling cost is a real concern, not hypothetical.

Tasks:
- Replace the detached window body with a `QSplitter(Qt.Horizontal)`:
  - left: answers rail, `PixelPanel(inner=True)`, section title "ANSWERS",
    minimum width ~280 px, initial split ~38/62;
  - right: the existing transcript viewport, unchanged in content.
  - Persist the splitter position and the window geometry in
    `preferences.json` so the layout survives a reopen.
- Left rail empty state, in theme: a short centered hint ("Right-click a
  transcript bubble to ask about it") so the column reads as intentional
  before BU113 lands.
- Keep the filter control in the transcript column header, not the window
  header, now that the window has two columns.
- Transcript reading polish (right column):
  - Smooth per-pixel scrolling: `setVerticalScrollMode(ScrollPerPixel)` on
    the scroll area, and a scroll step tuned so a wheel notch moves a
    consistent distance regardless of bubble height.
  - Keep the existing stick-to-bottom behavior, including while a bubble is
    growing via `append_text`; do not regress the BU103 fade rules (no fade
    on an extending bubble).
  - A sticky date/time separator row inserted when the gap between bubbles
    exceeds `TRANSCRIPT_MAX_GROUP_SECONDS * 5`, so long silences read as
    breaks instead of an unexplained jump.
  - Selectable bubble text for copy, without breaking click handling needed
    by BU113.
- Make the window resizable down to a usable minimum (~720x480) with both
  columns still legible; verify no horizontal scrollbar appears at minimum
  width.
