# BU029 — Database Schema for Transcriptions

Status:
Pending

Goal:
Add a new table to the database to store live transcriptions.

Context:
To persist the live transcriptions, we need to store them in the database. This BU will modify the database schema to include a new table for transcriptions.

Allowed Files:
- `src/storage/models.py`
- `src/storage/database.py`

Dependencies:
Required:
- BU028

Blocks:
- BU032

Tasks:
1.  **Modify `src/storage/models.py`:**
    - Define a new SQLAlchemy model for the `transcriptions` table. The table should include columns for `id`, `session_id`, `source` (mic or system), `timestamp`, and `text`.
2.  **Modify `src/storage/database.py`:**
    - In the `Database` class, add a new method to create the `transcriptions` table.
    - Create a new method, e.g., `add_transcription`, to insert a new transcription into the database.
    - In the `SessionManager`, call the `add_transcription` method after a chunk is transcribed.

Execution Sequence:
1.  **Understand:** Review the existing database schema and the `SQLAlchemy` models.
2.  **Implement:** Add the new `transcriptions` table and the corresponding methods to interact with it.
3.  **Validate:** After a session, connect to the database and verify that the transcriptions have been saved correctly. You can use a tool like `sqlite3` or a database browser.
4.  **Review Readiness:** Ensure the database schema is correct and the data is being saved as expected.
5.  **Document:** Update `docs/current_state.md` and `docs/devlog.md`.

Validation Requirements:

Required:
- The `transcriptions` table must be created in the database.
- Live transcriptions must be saved to the database during a session.
- No new syntax/runtime errors should be introduced.

Tests Required:
- no

Out of Scope:
- Displaying the transcriptions in the UI.

- [ ] Live transcriptions are saved to the database.
