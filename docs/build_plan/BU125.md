# BU125 — Windowed-App Hardening: Log File, Crash Dialog, Single Instance

Status:
Completed

Goal:
Make the app safe to run without a console. Output goes to a log file,
crashes show a dialog instead of vanishing, and a second launch focuses the
running app instead of starting a second recorder on the same database.

Context:
- `src/main.py` logs with `logging.basicConfig` to the console. A windowed
  PyInstaller build (`--noconsole`) has no console: `sys.stdout` and
  `sys.stderr` are `None`, so any `print()` or library write to them raises
  `AttributeError`, and uncaught exceptions disappear silently.
- Without a log file, a user reporting "it stopped transcribing" has nothing
  to send.
- Two instances would share `chronicle.db` (in WAL mode), both register the
  global hotkey (`src/app/global_hotkey.py`, where the second registration
  fails), and both could record at the same time.

Tasks:
- Logging: a `RotatingFileHandler` at `logs_dir()/chronicle.log` (5 MB x 3
  files), plus the console handler only when a console exists. Keep the
  existing per-module levels.
- If `sys.stdout` or `sys.stderr` is `None`, replace it with a writer that
  forwards to the log.
- `sys.excepthook` and `threading.excepthook`: log the traceback and show a
  `QMessageBox` with the short error, the log folder path and an "Open log
  folder" button. Qt-thread exceptions are logged without crashing the event
  loop.
- Single instance: a `QLocalServer` / `QLocalSocket` keyed per user. A second
  launch sends "activate" and exits, and the first instance raises and
  focuses its window.
- Add a "Help > Open log folder" menu entry.
