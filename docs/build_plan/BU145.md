# BU145 — No-Document Prompt Baseline

Status:
Completed

Goal:
Pin down, as golden tests, every prompt the Specific Session chat and the
detached window send today, so the Session Documents work (BU146-BU151) can
prove that a session with no documents is answered exactly as before.

Context:
- The user's hard requirement for Session Documents: with no document added,
  everything works as it does now. "As it does now" has to be something a test
  can compare against, written before any document code exists.
- Prompts are built in two places:
  - `AssistantAnswerService._build_messages` (`service.py` ~781), fed by
    `_retrieve_context` (~504). Two Specific Session layouts: BU144 whole
    transcript (`full_transcript`) and the search layout (`background` +
    per-question `evidence`), each with and without screenshots
    (`SCREENSHOT_CONTRACT`).
  - The detached window's answer cards: `answer_instruction(mode,
    reference_name)` (`live_qa.py` ~183) supplies the system instruction and
    `AssistantQueryThread._effective_agent_id` (`window.py` ~483) registers it;
    the question comes from the BU113/BU116 builders.
- Any Session (`_get_all_sessions_context` + `RESPONSE_CONTRACT`) must never
  read session documents; its prompt is pinned too, so a leak would show up.
- The OpenRouter call is already mocked in existing tests
  (`tests/test_bu144.py` builds messages without the network); reuse that
  setup rather than inventing a new harness.

Tasks:
- Build a small in-memory database fixture: one recorded session with a few
  transcript rows, a summary and two screenshots; one session with no
  screenshots; one inserted-text session (`origin='text'`); and a session
  longer than `SESSION["full_transcript_max_chars"]` (patch the limit down in
  the test rather than writing 300k chars).
- For each, capture the exact `messages` list `_build_messages` produces
  (OpenRouter mocked at `_call_openrouter` / `_call_openrouter_async`) for:
  - chat, Specific Session, whole-transcript layout, with and without
    screenshots;
  - chat, Specific Session, search layout (over the limit);
  - chat, Specific Session, a follow-up in an existing conversation (history
    replayed);
  - detached answer card, Transcripts mode, manual selection and detected
    candidate;
  - detached answer card, General Knowledge mode (`use_context=False`);
  - chat, Any Session.
- Store each as a golden JSON file under `tests/fixtures/prompt_baseline/`.
  The test compares byte-for-byte. Timestamps and anything clock-dependent are
  frozen in the fixture, not masked in the comparison.
- `answer_instruction(mode, "")` for every mode is pinned the same way.
- A `--update-baseline` path (env var `CHRONICLE_UPDATE_BASELINE=1`) that
  rewrites the golden files, documented in the test's docstring, for the day a
  prompt is changed on purpose. BU146-BU151 must not use it.
