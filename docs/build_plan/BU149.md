# BU149 — Session Documents In Specific Session Prompts

Status:
Completed

Goal:
When the session being asked about has documents, the Specific Session
prompt changes: the documents are added as labelled evidence, the model is
told how to weigh them against the transcript, and it reports which documents
it used so the UI can show a badge. With no documents, the prompt is
byte-for-byte what it is today.

Context:
- User decisions: transcript first; a document is used when it adds to or
  contradicts the transcript, and a contradiction is said out loud. Answers
  that used a document get a **UI badge** naming it (rendering is BU150 /
  BU151; this BU produces the data).
- Only Specific Session scope (`ScopeResolution.CURRENT_SESSION` /
  `SELECTED_SESSION`) reads documents. Any Session never does. After the
  BU092 handoff switches to a specific session, that session's documents
  apply because the question is now Specific Session.
- `use_context=False` (General Knowledge mode in the detached window) and the
  research helper's no-context path (`_needs_session_context` False) read no
  session context today, so they read no documents either.
- Prompt layout (`_build_messages`, `service.py` ~781) is ordered for prefix
  caching (BU144): system = instruction, screenshot contract, session
  header + whole transcript (last, so a live transcript only grows at the
  end); per-question evidence goes in the user message. Documents that are
  the same for every question belong in the system message, **before** the
  transcript; per-question excerpts belong in the user message.
- `reference_doc.select_relevant_excerpt` (BU117) already picks the best
  contiguous paragraphs for a question, deterministically. Reuse it per
  document for the excerpt case.
- Citation pattern to mirror: `screenshot_contract.py` (BU108) — a fixed
  final line the parser validates against ids actually sent.
- Only the bare question is persisted (`_persist_conversation`), so reopening
  an old conversation uses the documents the session has *now*.
- BU145 golden files are the regression check for the no-document case and
  must pass unchanged.

Tasks:
- Config (`SESSION_DOCUMENTS`):
  - `whole_total_max_chars` (e.g. 60000): if the session's documents together
    fit, all are sent whole; otherwise every document is sent as a
    per-question excerpt.
  - `excerpt_chars_per_document` (e.g. 4000).
- Loading: in `_get_single_session_context`, after the existing context is
  built, read `get_session_documents(session_id)`. **If the list is empty,
  return exactly what is returned today** — no new keys, no empty sections.
- Rendering (in `session_documents.py`, pure functions):
  - each document is headed `[D<id>] <name> (<type>)`;
  - whole mode: `## Session documents` with every document's full text, in the
    order added;
  - excerpt mode: `## Session document excerpts` with each document's
    `select_relevant_excerpt` for the question (stripped of the transcript
    evidence block, as BU117 does); documents whose excerpt is empty are
    listed by header only so the model knows they exist.
- Placement in `_build_messages`:
  - whole mode: in the system message, after the screenshot contract and the
    document contract, before `Context:` / the transcript, so the cached
    prefix is stable while a live transcript grows;
  - excerpt mode: in the user message, after the existing per-question
    evidence.
- `document_contract.py`:
  - `DOCUMENT_CONTRACT` text added to the system message only when documents
    exist: the transcript is the primary source; use a document to add
    information the transcript lacks, and if a document contradicts the
    transcript say so explicitly and name both; never present document
    content as something said in the session; if the answer used any
    document, end with exactly one final line `Documents used: D<id>, D<id>`
    (English, ids from the headers only); otherwise no such line.
  - `parse_document_refs(answer, allowed_ids) -> (answer_without_line, ids)`:
    looks at the last three non-empty lines, drops unknown ids, removes the
    line; never raises.
- `_finalize_answer`: when documents were in context, run
  `parse_document_refs` **before** `parse_screenshot_refs` (so the screenshot
  line is again among the last two). `AnswerResponse` gains
  `document_refs: List[Dict]` (`id`, `name`), default empty.
- Persistence: the stored assistant message keeps a normalised
  `Documents used: D<id>, ...` line so a reopened conversation can rebuild the
  badge (BU150); the `answer` returned to the UI has it removed.
- Detached-window answers: they already ask with
  `explicit_scope="current_session"`, so they get documents through this path
  automatically. This BU does not touch `window.py`; until BU151 the BU117
  `.txt` still rides on the question as before.
- Log, per answer: documents count, mode (`whole` / `excerpt`), document
  chars sent, and cited ids.
