# BU106 — Screenshot Preliminary Description And Metadata Optimization

Status:
Completed

Goal:
Give every screenshot a compact, retrieval-oriented preliminary description
that exists without any AI call, and tighten the vision-model metadata so it is
optimized for later lookup by the assistant.

Context:
The user wants the assistant to find screenshots from a two-tier view: first a
short description of each one, then the full metadata only for the ones that
matter. Today the `screenshots` table has `description`, `ai_summary`,
`visible_text` (JSON list) and `keywords` (JSON list), but:
- `description` is only set if the user types something into the
  `QInputDialog` shown after a snip (`ScreenshotCapture._prompt_for_description`),
  so it is usually NULL.
- `ai_summary` / `visible_text` / `keywords` exist only after a manual
  "Give Context" click, which `window.py` gates on the session having a
  summary, so live and unsummarized sessions never get them.
- The transcript excerpt passed to `ScreenshotContextGenerator` is "nearest 2
  transcript rows, 200 chars each" (built twice in `window.py`: the
  single-screenshot handler and `ScreenshotContextBatchThread`), while the
  prompt tells the model it is "approximately 40 seconds around the screenshot".
- The generator's JSON schema has no short field suitable as an index entry,
  and `_parse_response` returns the first regex match without normalizing
  field presence or types.
- There is no column that can serve as a cheap Tier-1 description.

Tasks:
- Schema: add `preview_description TEXT` and `preview_source TEXT`
  (`'auto'` | `'ai'`) to the screenshots column-migration list, using the same
  mechanism that added `ai_summary`. No data backfill at startup.
- Add DB helpers: `update_screenshot_preview(screenshot_id, text, source)` and
  `get_screenshot_previews(session_id)`, which returns only `id`, `timestamp`,
  `description`, `preview_description`, `preview_source`, `keywords` (no
  `ai_summary` / `visible_text`). This is the Tier-1 read.
- Create `src/screenshots/metadata.py` (pure, no Qt, no network):
  - `transcript_window(transcripts, ts, before=20, after=20, max_chars=1200)`:
    chronological text of the transcript rows overlapping `[ts-before, ts+after]`;
    falls back to the 2 nearest rows when the window is empty.
  - `build_preliminary_description(row, transcripts, session_start=None)`:
    deterministic text of at most 240 chars: the user description first (if
    any), then a condensed "Discussed: ..." from `transcript_window`, then
    the capture time label (`HH:MM:SS`, plus the offset into the session when
    `session_start` is known).
  - `ensure_previews(db, session_id)`: for rows whose preview is NULL or
    `preview_source='auto'`, rebuild from current transcripts and persist
    only when the text changed. Never overwrites `preview_source='ai'`. Cheap
    enough to call at retrieval time, so a live session's previews improve
    as more transcript arrives.
- Context generator:
  - Add `short_description` to the JSON schema: at most 25 words describing
    what is on screen and the topic being discussed, written for lookup
    ("Jira board for Q3 release, discussing blocked auth tickets"). Tell the
    model not to open with filler like "This screenshot shows".
  - Update the prompt's excerpt wording to match the real ±20 s window.
  - Normalize `_parse_response` output so it always has `summary` (str),
    `short_description` (str), `visible_text` (list[str]) and `keywords`
    (list[str]), coercing strings or None into the right type.
  - `_store_context` also writes `short_description` into
    `preview_description` with `preview_source='ai'`, next to the fields it
    already stores.
- Replace both "nearest 2 transcripts × 200 chars" excerpt builders in
  `window.py` with `transcript_window`.
