# BU096 — Delete Past Conversation From Sidebar (Right-Click)

Status:
Pending

Goal:
Let the user permanently delete a past assistant conversation directly from the
"PAST CONVERSATIONS" sidebar list: right-click a conversation → "Delete" →
confirm → the conversation and every trace of it are removed from the database
and the UI. This is about the assistant chat threads (`assistant_conversations`
/ `assistant_messages`), not meeting sessions — session deletion already exists
(`_delete_session` / `_delete_session_by_id` / `db.purge_session`).

Context:
- The sidebar list is `self.conversations_list` (a `QListWidget`) built in
  `MainWindow` around `src/app/window.py:2372`. Each item stores its
  `conversation_id` in `Qt.UserRole` and is populated by
  `_load_past_conversations()` (`src/app/window.py:486`). Today it only wires
  `itemClicked` → `_on_conversation_selected`; there is no context menu and no
  way to remove a conversation from the UI at all.
- The database already has `db.delete_conversation(conversation_id)`
  (`src/storage/database.py:848`), which deletes the `assistant_messages` rows
  then the `assistant_conversations` row in one transaction. Conversations are
  **not** indexed into RAG (`rag_documents` / `rag_chunks` / `rag_fts` have no
  conversation `source_type`), so there is no RAG cleanup to do — "any trace"
  here means the two conversation tables plus the app's in-memory references.
- In-memory / UI state that also references a conversation id and must not be
  left dangling after a delete:
  - `MainWindow._current_conversation_id` (and the detached window's copy) — if
    the deleted conversation is the one currently loaded in the assistant panel,
    the view must be reset (reuse `_on_new_chat_clicked()` semantics: clear both
    views, reset `_current_conversation_id`, drop `_pending_scope_prompt`).
  - `AssistantAnswerService._declined_offers` (`src/assistant/service.py:91`) —
    a `Dict[Optional[int], Set[int]]` keyed by `conversation_id`. Drop the
    deleted conversation's entry so a recycled id cannot inherit stale declines.
  - The "Past Conversations" modal dialog (`_on_past_conversations_clicked`,
    `src/app/window.py:5298`) and "Search Chats" both read `db.list_conversations()`
    live, so they need no change beyond being reopened.
- Pattern to mirror: `_show_session_context_menu` / `_delete_session`
  (`src/app/window.py:732`), which does `QListWidget`-style right-click →
  `QMenu` → `QMessageBox.question` confirm → delete → remove row → status update.

Tasks:
1. `conversations_list` context menu (`src/app/window.py`):
   - Set `self.conversations_list.setContextMenuPolicy(Qt.CustomContextMenu)` and
     connect `customContextMenuRequested` to a new
     `_show_conversation_context_menu(position)`.
   - `_show_conversation_context_menu`: resolve the item under `position` via
     `self.conversations_list.itemAt(position)`; return if none. Build a `QMenu`
     with a single `"Delete"` action (add a `"Load Conversation"` action too only
     if it is trivial — otherwise keep scope to Delete). `exec` at
     `self.conversations_list.mapToGlobal(position)`; on Delete call
     `_delete_conversation(item)`.
2. `_delete_conversation(item)` (`src/app/window.py`):
   - Read `conv_id = item.data(Qt.UserRole)`; return if `None`.
   - `QMessageBox.question` confirm: "Permanently delete this conversation? This
     removes it and all its messages from the database and cannot be undone."
     Default button `No`.
   - On Yes:
     - `self.session_manager.db.delete_conversation(conv_id)`.
     - If `self._current_conversation_id == conv_id`: call the existing
       new-chat reset path so the assistant panel (and detached window, if open)
       no longer shows the deleted thread.
     - Best-effort `self.assistant_service.forget_conversation(conv_id)` (new
       thin method, task 4) guarded so a missing service / key error never
       raises.
     - `self._load_past_conversations()` to rebuild the list, then
       `self._on_status_update("Conversation deleted.")`.
   - Wrap DB + refresh in `try/except`, log with `logger.error`, and show a
     `QMessageBox.warning` on failure — same shape as `_delete_session`.
3. `db.delete_conversation` hardening (`src/storage/database.py:848`):
   - Confirm it is a no-op (not an error) for an unknown `conversation_id`
     (SQLite `DELETE` of 0 rows already is — just document it in the docstring).
   - Leave the existing single-transaction ordering (messages → conversation) as
     is.
4. `AssistantAnswerService.forget_conversation(conversation_id)`
   (`src/assistant/service.py`):
   - `self._declined_offers.pop(conversation_id, None)`. Keep it a one-liner with
     a docstring; no DB access. (If any other per-conversation in-memory cache is
     added later, this is the single hook to clear it.)
5. Wire the new service method call site defensively in `window.py` (getattr /
   hasattr guard so older service instances don't break the delete).

Validation Requirements:

Required:
- Right-clicking a conversation in the sidebar shows a "Delete" menu.
- Confirming removes the conversation row from `assistant_conversations` and all
  its rows from `assistant_messages` (verified by a direct DB query in a test).
- After deletion the conversation is gone from the sidebar list, from the "Past
  Conversations" dialog, and from "Search Chats" results.
- Deleting the currently-loaded conversation clears the assistant panel (and the
  detached window if open) without a crash; a subsequent Ask starts a fresh
  conversation.
- Deleting a non-loaded conversation leaves the current chat untouched.
- Cancelling the confirmation dialog changes nothing.
- No `Qt.CustomContextMenu` regression on the sessions list or other lists.

Tests Required:
- yes

Tests (DB-level, no Qt harness — same constraint noted in BU093/BU095):
- `delete_conversation` removes the conversation and cascades to its messages;
  a second call with the same id is a silent no-op.
- `delete_conversation` on one conversation does not touch a sibling
  conversation's messages.
- `list_conversations()` / `find`-style lookups no longer return the deleted id.
- `AssistantAnswerService.forget_conversation` drops the `_declined_offers`
  entry and is a no-op for an unknown id.

Out of Scope:
- Multi-select / bulk delete of conversations.
- Undo / soft-delete / trash for conversations.
- Any change to meeting-session deletion.
- Deleting conversations from inside the "Past Conversations" modal or "Search
  Chats" dialog (sidebar right-click only for this BU; the modal can be a
  follow-on if wanted).
- Archiving conversation transcripts to disk before delete (conversations live
  only in the DB).
- Keyboard shortcut for delete.
