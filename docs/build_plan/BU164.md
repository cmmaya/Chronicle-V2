# BU164 — Speaker Transcript Storage

Status:
Completed

Goal:
Store a diarized transcript next to the original one, and let every
reader get the diarized version when a session has diarization enabled,
without ever changing the original rows.

Context:
- Stored transcripts have no word timings, so their text cannot be split
  by speaker afterwards; BU165 re-transcribes each speaker turn. The result
  needs its own table.
- Many readers call `db.get_transcripts(session_id)` (main view, detached
  window, assistant context, RAG indexer, screenshot metadata). Switching
  inside that one method keeps them all consistent.
- SCHEMA_VERSION is 5; migrations back up the database first.

Tasks:
- Schema v6:
  - table `diarized_transcripts` (id, session_id, timestamp, end_timestamp,
    text, source, speaker INTEGER, audio_file), index on session_id
  - sessions: `diarization_status TEXT DEFAULT 'none'`
    ('none' | 'running' | 'ready' | 'failed'),
    `diarization_enabled INTEGER NOT NULL DEFAULT 0`
- `replace_diarized_transcripts(session_id, rows)` in one transaction.
- `get_transcripts(session_id)`: diarized rows (with a `speaker` key) when
  enabled and ready, otherwise the original rows (no `speaker` key).
- `get_original_transcripts(session_id)`: always the original rows.
- `set_diarization(session_id, enabled=..., status=...)`;
  `list_sessions_with_flags` returns both fields and the speaker count.
- delete_session / delete_transcripts also delete diarized rows; a
  re-transcription clears them and sets the status back to 'none'.
