# BU165 — Diarization Job

Status:
Completed

Goal:
Run a session's diarization in the background from start to finish:
download the models if needed, find the speakers, transcribe each turn,
store, switch the session over and re-index it.

Context:
- SessionManager has one background job thread shared by transcription,
  summaries, imports and documents. A 30-minute diarization there would
  hold all of them up, so it gets its own worker.
- Parakeet (src/transcription/parakeet.py) transcribes an audio array;
  long turns must be split.

Tasks:
- One diarization worker thread; one session at a time, others queue.
- Stages and overall progress (shown by BU167):
  1. downloading models (only if missing): 0-5%
  2. finding speakers (BU163): 5-75%
  3. transcribing speakers (turns split at 30 s): 75-97%
  4. saving and re-indexing (RAG content + session profile): 97-100%
- `start_diarization(session_id)`, `cancel_diarization(session_id)`,
  `enable_diarization(session_id)` (instant when the status is 'ready'),
  `disable_diarization(session_id)` (back to the original transcript and
  re-index; diarized rows kept, so enabling again is instant).
- Callbacks to the UI thread: progress(session_id, percent, text),
  finished(session_id, ok, error).
- Refused for: a live session, a session with no audio files (inserted
  transcripts), a session not yet transcribed.
- Startup repair: a session left 'running' by a crash becomes 'failed'.
- Cancel leaves the session exactly as before (prior status, nothing
  written).
