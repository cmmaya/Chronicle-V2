# BU151 — Detached Window On Session Documents (Replaces The BU117 Attachment)

Status:
Completed

Goal:
The detached transcripts window uses the session's documents instead of its
own one-file attachment: a file dropped on it is added to the session, the
header chip shows the session's documents, and answer cards that used a
document show the same badge as the chat. One document system, not two.

Context:
- User decision: one system. BU117's window-held `.txt` (`_reference_doc`,
  `_attach_reference_doc`, `_with_reference_evidence`, `PixelReferenceChip`;
  `window.py` ~4719-4800, ~5381) is retired in favour of BU146's table.
- Since BU149, detached answer cards already receive the session's documents
  through the service (`explicit_scope="current_session"`). Keeping
  `_with_reference_evidence` would send document text twice, so it goes.
- The card's answer format (BU116/BU117) is tiered:
  `From transcripts:` / `From <file>:` / `General knowledge:`. With no
  documents the instruction must stay exactly
  `LIVE_QA["answer_instructions"][mode]` (pinned by BU145). With documents the
  middle tier becomes `From documents:` and the badge names which document
  (user chose a badge over inline names); the BU149 `Documents used:` line
  supplies the ids.
- General Knowledge mode ignores documents (`use_context=False`) — unchanged.
- `DetachedTranscriptsDialog` (~292) already handles drag-enter / drop with
  the themed overlay; its extension check moves from `REFERENCE_DOC` to
  `session_documents.is_allowed_document`.
- The window shows `_current_display_session_id()`; a drop adds to that
  session. If no session is displayed, the drop is refused with a message.

Tasks:
- Drop / pick on the detached window: runs the BU148 import flow
  (`extract_document` → `add_session_document` on a background job) for the
  displayed session; accepts every `SESSION_DOCUMENTS` type; multiple files
  allowed; limit / duplicate / extraction errors go through
  `_on_status_update` as today.
- Header chip: replace `PixelReferenceChip` usage with a documents chip
  "📄 N documents" (reuse BU150's indicator widget) that opens
  `SessionDocumentsDialog`. Hidden when the session has none — the header then
  looks exactly as BU115/BU116 left it. Refreshes on `documents_changed` and
  when the displayed session changes.
- Remove the window-held state and the double send: `_reference_doc`,
  `_attach_reference_doc`, `_clear_reference_doc`, `_pick_reference_doc`,
  `_with_reference_evidence`, `_reference_evidence_name`, and the
  close-window cleanup for them. `PixelReferenceChip` goes if nothing else
  uses it.
- `live_qa.answer_instruction(mode, has_documents: bool = False)`:
  - `has_documents=False` → returns exactly today's
    `LIVE_QA["answer_instructions"][mode]` (BU145 golden);
  - `True` and mode is Transcripts → a documents variant of the three-tier
    instruction (`From transcripts:` / `From documents:` /
    `General knowledge:`), replacing `REFERENCE_DOC["answer_instruction"]`;
    it tells the model to also end with the BU149 `Documents used:` line;
  - General mode ignores the flag.
  The window passes `has_documents` from `count_session_documents` for the
  displayed session.
- Answer cards: `PixelAnswerCard` gains `set_document_badge(names)`; on
  finish, `response.document_refs` non-empty → badge under the answer.
- `REFERENCE_DOC` config: remove what is no longer read; keep
  `max_excerpt_chars` only if BU149 still uses it via `select_relevant_excerpt`
  (otherwise move it under `SESSION_DOCUMENTS`). `reference_doc.py` keeps the
  loader and excerpt functions BU147/BU149 reuse; drop the rest.
- BU117.md: one line under Status noting it is superseded by BU151.
