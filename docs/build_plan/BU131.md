# BU131 — Calendar Page In The Settings Pop-Up

Status:
Completed

Goal:
Add a **Calendar** page to the Settings pop-up (BU128). From it the user
connects or disconnects a Google account, sees which account is connected,
picks the calendar that new events go to, and chooses between the Chronicle
OAuth client and a custom one.

Context:
- `SettingsDialog` (`settings_dialog.py`) builds pages with `_page(name,
  build)`. Each setting is a `_SettingCard` (title, muted description, control
  on the right). Changes apply immediately, and there is no OK/Cancel.
- The API Key page (`_build_api_key`) already runs a network check on a
  `QThread` (`ApiKeyCheckThread`) and shows a result. The Calendar page follows
  that pattern for sign-in and for listing calendars.
- BU130 provides `SignInFlow`, `disconnect()`, `connection_state()`,
  `load_client()` and `import_custom_client()`.
- Choosing a calendar needs the calendar list
  (`GET /users/me/calendarList`, `minAccessRole=writer`). The
  `calendar.events` scope does not grant the calendar list. See the decision
  below.

Decisions:
- Target calendar: always the account's **primary** calendar for now, shown
  as "Primary calendar (<email>)". A picker would need the extra
  `calendar.calendarlist.readonly` scope. Deferring it keeps the consent screen
  to one permission.
  - Open question for the user: is a picker needed now? If yes, add that scope
    in BU130 and a combo box here.
- Changing the client source while connected requires a disconnect first. A
  refresh token belongs to the client that issued it.

Tasks:
- `SettingsDialog`: a new **Calendar** nav entry between API Key and
  Maintenance, with these cards:
  - **Google account**: shows "Not connected" or "Connected as <email>", with
    a **Connect** / **Disconnect** button.
    - Connect starts `SignInFlow` on a worker thread. While it waits, the
      button reads "Waiting for browser…" and a **Cancel** button appears. On
      success the email shows. On failure (cancelled, permission missing,
      timeout, network) a muted error line shows under the card.
    - Disconnect asks for confirmation ("Chronicle will no longer be able to
      add events. Events already created stay in your calendar.") and then
      calls `disconnect()`.
  - **Calendar**: read-only "Primary calendar" while connected.
  - **OAuth client**: a two-option choice, "Chronicle (recommended)" /
    "Custom". Custom shows an **Import client_secret.json…** button and the
    imported client ID (truncated). Chronicle is disabled, with the hint
    "Not available in this build", when no bundled client exists. Changing
    the source while connected is disabled, with the hint "Disconnect first".
- `window.py`: `open_settings(page="Calendar")` so BU133 can send the user
  straight to this page.
- The dialog must not block while sign-in runs. Closing Settings mid-flow
  cancels the flow.
