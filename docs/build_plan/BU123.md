# BU123 — Model Manager: Check, Download And Verify Models

Status:
Completed

Goal:
One headless service that knows which models the app needs, whether they are
already on disk, and how to download them with progress reporting. This way
the setup wizard (BU124) can install them up front, and the app never
downloads silently in the middle of a recording.

Context:
- The app needs two model sets from Hugging Face:
  - Parakeet `nemo-parakeet-tdt-0.6b-v3`, loaded by
    `onnx_asr.load_model(...)` (`src/transcription/parakeet.py:192`), with a
    quantized variant tried first and full precision as the fallback
    (`parakeet.py:185-205`). Together that is roughly 0.7-2.5 GB depending on
    which variants are fetched. Measure it during Understand.
  - Embeddings `intfloat/multilingual-e5-small`, pinned to revision
    `614241f6...` (`src/rag/embeddings.py:37-38`): `onnx/model.onnx` and the
    tokenizer, about 0.5 GB.
- Today both download lazily the first time they are used. For Parakeet that
  is the first transcription, which means a silent pause of several minutes
  inside a live session, with no progress and no clear error if offline.
- The quantized-then-full fallback means an incomplete install currently
  "works" by downloading the other variant at runtime. The manager must fetch
  exactly the variant the config will load.
- `HF_HOME` points at `models_dir()` (BU121).

Tasks:
- `src/model_manager.py`:
  - `REQUIRED_MODELS`: a list of `(name, repo_id, revision, files)`, with the
    Parakeet repo and file list resolved from what `onnx_asr` actually loads
    for the configured quantization. Pin the Parakeet revision like e5
    already is.
  - `status() -> list[ModelStatus]`: installed, missing or incomplete per
    model, plus the total bytes still to download. Checks files on disk only,
    with no network use.
  - `download(progress_cb, cancel_event)`: fetches the missing files with
    `hf_hub_download`, reporting `(model, bytes_done, bytes_total)`. It
    resumes partial files, stops cleanly on cancel, and raises a typed error
    (`OfflineError`, `DiskFullError`, `DownloadError`) with a readable
    message.
  - Checks free disk space before starting and refuses early with the number
    of GB needed.
- Once `status()` reports everything installed, the app sets
  `HF_HUB_OFFLINE=1` for the rest of the run. Loaders then use the local
  files and never reach the network. A missing model becomes a clear error
  instead of a surprise download.
- Parakeet and the embedder stop falling back to a download at runtime. If
  their files are missing, they raise an error that says to run setup.

Validation Requirements:

Required:
- executable behavior verified
- no syntax/runtime errors
- Definition of Done satisfied
- manual validation:
  - With an empty `CHRONICLE_DATA_DIR`, run a download from a small script:
    progress rises to 100%, then `status()` reports everything installed.
  - Kill it halfway through, run it again, and confirm it resumes instead of
    restarting.
  - Disconnect the network and confirm a readable `OfflineError`.
  - With the models installed and the network off, start a session and
    confirm live transcription and RAG routing both work.

Tests Required:
- yes — `status()` for installed, missing and partial files (temp folder, no
  network); the download loop with `hf_hub_download` mocked (progress
  callback, cancel, and each error mapping); disk-space refusal; offline mode
  set only when everything is installed
