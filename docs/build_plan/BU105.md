# BU105 — Performance, Memory, and Threading Rework

Status:
Completed

Goal:
Bring the app's RAM use down from the 2.5-3.5 GB the user was seeing to
roughly 1-2 GB, and make Stop/Pause/Close never freeze the UI. Requested
directly by the user after a walkthrough of the whole capture -> transcribe
-> store -> UI pipeline and a read-only audit of `chronicle.db`.

Context:
Three compounding causes were found:
1. Live transcription ran inline, inside the microphone's PortAudio
   callback and inside the system-audio poll loop - so a ~0.5-1s inference
   (or the ~6-8s model load on the first chunk) blocked audio capture, and
   Stop had to wait for it plus a full transcribe/index/summarize pass
   before the button ever returned.
2. Up to three separate Parakeet model copies could be resident at once
   (live mic, live system-audio-triggered load, and a fresh
   `TranscriptionProcessor` on Transcribe/Stop), each ~2.6 GB, plus the
   RAG embedding model computed in one unbatched call per session.
3. `chronicle.db` had no per-session-thread connection handling (a shared
   connection across threads with no WAL), no indexes on the hot paths
   (`transcripts.session_id`, `assistant_messages.conversation_id`, ...),
   rebuilt the *entire* FTS index on every single session's re-index, and
   carried leftover `rag_documents`/`rag_chunks`/`session_profiles`/
   `assistant_conversations`/`screenshots` rows for 25+ sessions deleted
   before `purge_session` existed - which the "Any Session" fallback search
   path could still surface in answers.

Tasks:

Database (src/storage/database.py):
- Per-thread connections (`threading.local`, one SQLite connection per
  calling thread, opened lazily) instead of one connection shared across
  the UI, live-transcription and job threads; `release_thread_connection()`
  for a short-lived thread to give its connection back; `disconnect()`
  closes every thread's connection.
- WAL journal mode + `synchronous=NORMAL` so readers never block the writer.
- `SCHEMA_VERSION` + `PRAGMA user_version`-driven migration
  (`_migrate`), auto-backing up the file (`.bak-v<from>-<timestamp>`)
  before a migration that touches an existing (not freshly-created)
  database; `auto_vacuum=INCREMENTAL` + a one-time `VACUUM` on migration.
- New columns: `transcripts.end_timestamp` / `audio_file` (which chunk a
  row came from, so batch transcription can skip it) and
  `sessions.needs_finalize`.
- Indexes: `sessions(start_time)`, `transcripts(session_id, timestamp)`,
  `screenshots(session_id, timestamp)`, `screenshots(filepath)`,
  `summaries(session_id, created_at)`, `assistant_conversations(session_id)`,
  `assistant_conversations(updated_at)`, `assistant_messages(conversation_id,
  timestamp)`.
- `rag_fts` rows now share their chunk's id as `rowid`, so
  `replace_rag_chunks` can update one document's FTS rows directly instead
  of every indexing pass rebuilding the whole table
  (`rebuild_rag_fts`/`_rebuild_rag_fts` kept for an explicit full rebuild).
- `purge_orphans()` / `_purge_orphans()`: removes `rag_documents` /
  `rag_chunks` / `rag_fts` / `session_profiles` / `assistant_conversations`
  (+ their messages) / `transcripts` / `screenshots` / `summaries` rows
  whose session no longer exists; run once automatically as part of
  migration and again at every `SessionManager` startup. `search_rag_fts`
  additionally filters out any chunk whose session doesn't exist, so a
  leftover row already in the wild can't surface in an answer even before
  cleanup runs.
- `repair_interrupted_sessions()`: a session still `active`/`paused`/
  `processing` at startup (app closed or crashed mid-session) becomes
  `stopped` with `needs_finalize=1`. `list_sessions_needing_finalize()` /
  `list_sessions_with_flags()` (one EXISTS-based query for `has_transcripts`
  / `has_summary` across every session, replacing a `get_transcripts()` /
  `get_summaries()` round trip per row in the All Sessions list).
- `get_transcribed_chunk_keys()`: the `audio_file` (or, for older rows, the
  `(source, timestamp)` fallback) of every transcript a session already has,
  used by `TranscriptionProcessor._already_transcribed`.
- Fixed `get_recent_messages` returning the *oldest* N messages instead of
  the most recent N (wrong sub-query bound).

Speech model (src/transcription/parakeet.py, src/rag/embeddings.py):
- `get_shared_engine()`/`set_shared_engine()`: one process-wide
  `ParakeetEngine`, thread-safe (`_load_lock` for the model, `_infer_lock`
  serializing inference - the model itself isn't thread-safe under
  onnxruntime). Replaces a separate engine per `LiveTranscriber` and per
  `TranscriptionProcessor`, which is what let two-to-three ~2.6 GB copies
  load at once.
- `enable_cpu_mem_arena=False` on both the Parakeet and the e5 embedding
  ONNX Runtime sessions: the arena keeps every allocation's high-water mark
  for the model's lifetime; without it, memory an inference used is given
  back afterward.
- `idle_seconds()` / `unload()` on both, driven by
  `TRANSCRIPTION['idle_unload_seconds']` (300s default) from
  `TranscriptionWorker`'s idle callback - measured: fp32 Parakeet
  2593 MB -> 83 MB on `unload()`, reload in ~5s.
- `embed_passages()` now batches (16 passages/call, longest-first grouping)
  instead of one call per session; measured on a 138-chunk session: peak
  RSS 1963 MB -> 1167 MB unbatched->batched, and faster (14.5s -> 11.5s).
- `config.TRANSCRIPTION['quantization']`: int8 support added
  (`onnx_asr.load_model(..., quantization="int8")`, falling back to fp32 if
  the quantized weights can't be loaded) but left off by default - measured
  on this machine (AMD Ryzen 7 4800H, no AVX-VNNI) at ~750 MB vs ~2.6 GB for
  fp32, but ~26-46% of words differed from fp32 on real session audio,
  including several sentences returned empty. Not worth the memory here;
  documented in config.py so it can be revisited on different hardware.

Live transcription (src/transcription/worker.py new, src/transcription/live.py,
src/audio_capture/core.py):
- New `TranscriptionWorker`: one background thread with a queue.
  `submit(session_id, source, chunk)` never blocks; the worker transcribes
  in submission order, calling `on_result` per chunk and `on_status` for
  model-load progress. `wait_idle(session_id)` lets Stop's finalize step
  wait only for that session's queued chunks; `preload()` starts loading
  the model as soon as a session starts, ahead of the first chunk;
  `forget_session()` drops a finished session's dedup state.
- `LiveTranscriber`'s context/dedup state moved from one shared
  `_last_text` / `_context` to a dict keyed by `stream` (defaults to
  `(session_id, source)`) - the old shared state compared a mic chunk
  against the previous *system* chunk (or a previous session, once a
  shared engine made that possible), which can never find a real overlap
  and risks stripping words that merely start the same way.
  `forget_session(session_id)` drops every stream of that session.
- `ChunkedAudioRecorder`'s microphone `sounddevice` callback now only
  copies the incoming block into a `deque` (`_recording_loop`); resampling
  to the storage rate (via a new `_StreamResampler`, PyAV/FFmpeg), VAD, and
  writing the WAV all moved off the callback into the recorder's own
  polling loop (`_drain_raw` / `_feed` / `_emit_ready_chunks`). Previously
  VAD + WAV write + (before this BU) inline transcription ran *inside* the
  PortAudio callback, which is exactly the kind of work that overflows the
  input buffer and silently drops audio.
- Chunks are stored at `AUDIO_CAPTURE['storage_sample_rate']` (16 kHz,
  Parakeet's native rate) instead of the capture device's rate (44.1/48
  kHz) when PyAV is available - about a third of the previous disk use per
  session (measured: 2.78 MB vs 7.68 MB for the same 70s of speech).
- `SystemAudioRecorder.drain_buffer()`: atomically takes and clears the
  buffer under one lock, replacing a `get_audio_data()` + `clear_buffer()`
  pair that could lose a block appended by the capture thread in between.
- `TranscriptionProcessor._already_transcribed(session_id)`: predicate used
  by `_process_audio_by_source` and `process_new_chunks` to skip any audio
  file already covered by a transcript row (by `audio_file`, or by
  `(source, start-of-filename timestamp)` for rows written before that
  column existed) - batch transcription used to unconditionally
  re-transcribe (and re-insert) every chunk, duplicating every line of a
  session that used live transcription.
- `TranscriptionProcessor(engine=...)` / defaults to `get_shared_engine()`
  when no `model_path`/`engine` is given, so a fresh processor never pulls
  in a second model copy; `process_all` no longer eagerly loads the model,
  so a session fully covered by live transcription loads none at all.

Session lifecycle (src/app/session_manager.py, rewritten):
- `_JobRunner`: one daemon thread running background jobs
  (finalize/transcribe/summarize) in submission order, so two never
  compete for the CPU or hold two models' worth of work at once.
  `wait(timeout)` (a `Condition` on a busy counter) lets `close()` avoid
  disconnecting the database while a job's `fn()` - which owns that
  thread's DB connection - is still running.
- `stop_session(auto_transcribe=True, background=False, finalize=True)`:
  stopping capture is now separate from *finalizing* (transcribing
  whatever wasn't live, indexing, the optional auto-summary).
  `background=True` queues `finalize_session` on the job runner and
  returns immediately; the session stays flagged `needs_finalize=1` until
  it completes. `finalize=False` (used by `close()`) skips finalizing
  altogether - the session is picked up by `finalize_pending_sessions()`
  on the next start.
- `close()` stops capture without finalizing, drains the live-transcription
  worker (bounded `CLOSE_DRAIN_SECONDS`), and only disconnects the database
  once the job runner is idle (or after the same bounded wait) - closing
  used to always call `stop_session()` with its default `auto_transcribe=
  True`, which re-transcribed every audio file (loading a second model
  copy) and could block quitting for minutes.
- `_recover_after_restart()`: on every startup, repairs sessions the last
  run left `active`/`paused`/`processing` and purges orphaned rows, before
  any new session can start. `finalize_pending_sessions()` queues
  finalization (in the background) for every `needs_finalize` session.
- `transcribe_session(session_id)` / `summarize_session(session_id)`:
  blocking primitives (meant to be run via `submit_job`) that replace
  `window.py` calling `TranscriptionProcessor`/`SummaryGenerator` directly.
- Live transcription results are queued (`_live_callback_for`,
  `handle_live_transcription`) rather than transcribed inline; results are
  saved with their `audio_file` key so the batch pass can recognize them.
- `_unload_idle_models()` (run by `TranscriptionWorker`'s idle callback):
  unloads the shared Parakeet engine and the embedding model once neither
  has been used for `TRANSCRIPTION['idle_unload_seconds']` and nothing
  (an active session, a running job, a queued chunk) still needs them.

UI (src/app/window.py):
- `_status_ready` / `_session_finalized_ready` / `_ui_callback_ready`: Qt
  signals connected with `Qt.QueuedConnection`, since `SessionManager` now
  calls `status_callback` / `session_finalized_callback` from its worker
  and job threads (previously only ever the UI thread).
  `_on_status_update`/`_on_session_finalized` only emit;
  `_apply_status_update`/`_apply_session_finalized` do the actual widget
  work. `_post_to_ui(fn)` is the same pattern for a `submit_job()`
  completion callback, which runs on the job thread.
- `_on_stop_session`: calls `stop_session(auto_transcribe=True,
  background=True)` and shows "Finalizing..."; `_apply_session_finalized`
  reports the outcome and refreshes the session list (and an open All
  Sessions window, via `_all_sessions_dialog`).
- `_run_transcription` / `_run_summarization` (used by both the dead
  `sessions_list` combo path and the live All Sessions "•••" menu) and the
  BU104 Upload Audio flow (`_upload_audio_from_all_sessions` /
  `_transcribe_uploaded_session`) now submit jobs via
  `SessionManager.submit_job` instead of running
  `TranscriptionProcessor`/`SummaryGenerator`/`import_audio_file`
  synchronously on the UI thread.
- `closeEvent`: calls `stop_session(finalize=False)` instead of the default
  (finalizing) `stop_session()`.
- `_init_session_manager`: calls `finalize_pending_sessions()` once at
  startup.
- `_current_display_session_id()` / `_on_live_transcription`: a live result
  now carries `session_id` (queued results can lag a few chunks behind
  capture), and is only appended to the view if it matches the session
  actually on screen - previously any live result was shown regardless of
  which session the user had since switched to.
- `_load_sessions_for_browser` uses `db.list_sessions_with_flags()` (one
  query) instead of `get_transcripts()`/`get_summaries()` per session.
- `add_transcription_to_view(..., animate=False)`: the opacity fade-in
  plays only for a chunk arriving live, not for the bulk replay of a
  session's history in `_load_transcripts_for_session` (which used to fire
  one `QPropertyAnimation` per historical bubble).
- `_load_thumbnail(filepath, w, h)`: decodes screenshot thumbnails with
  `QImageReader.setScaledSize` instead of `QPixmap(filepath).scaled(...)` -
  the latter decodes the image at full screen resolution before throwing
  most of it away scaling down to 300x200.
- Each `QThread` (`ScreenshotContextThread`, `ScreenshotContextBatchThread`,
  `AssistantQueryThread`, `RagBackfillThread`) releases its thread-local DB
  connection (`db.release_thread_connection()`) in a `finally` block before
  exiting, instead of leaking one open SQLite connection per run.
- Resume is now also offered for a session in `processing` status (matches
  `resume_stopped_session`, defensive: startup repair should already have
  moved it to `stopped`).

Definition of Done:
[x] Live transcription never blocks audio capture (moved to a background
    queue; the mic callback only copies the buffer)
[x] Stop returns immediately; transcribe/index/summarize run in the
    background and report completion
[x] Closing the app never re-transcribes and never blocks on finalization
[x] At most one Parakeet model copy resident at a time, unloaded after
    5 minutes idle; the app returns to well under 1 GB idle
[x] Batch transcription never re-transcribes (or duplicates) a chunk live
    transcription already covered
[x] `chronicle.db` runs in WAL mode with per-thread connections, is
    migrated forward with an automatic backup, has indexes on every hot
    lookup, and no longer carries or surfaces rows for deleted sessions
[x] A session left active/paused/processing by a crash or force-quit is
    repaired and finalized automatically on the next start
[x] Existing test suite: zero regressions (verified against the
    pre-existing code via `git stash`)
