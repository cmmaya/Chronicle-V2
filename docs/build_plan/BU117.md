# BU117 — Reference .txt File As An Answer Source

Status:
Completed

Superseded by BU151: the window-held .txt is replaced by session documents.

Goal:
Let the user drop a .txt file onto the detached transcripts window and have its
contents used as evidence when answering, so material the meeting refers to but
never says out loud — a syllabus, a spec, an agenda, a problem set — can be
answered from.

Context:
- Live answers today see only the session's own transcript. A lecture that says
  "as in exercise 4" cannot be answered from, because exercise 4 is in a
  handout the recording never contains.
- The user asked specifically for drag-and-drop of a `.txt` file. Plain text
  keeps this BU to one concern: no parsing, no extraction, no format detection.
  PDF, .docx and .md are deliberately out of scope until the plain path is
  proven useful.
- This is an *answer-side* evidence source. It must not touch the recording
  pipeline, must not be indexed into RAG (`src/rag/`), and must not be written
  to the database — it is a scratch reference attached to the open window, the
  same way the answers rail is.
- BU116 owns the two answer modes and the instruction routing. This BU adds a
  third evidence tier inside the Transcripts mode: transcript first, reference
  document second, general knowledge last — each labelled so the user can see
  which one answered.
- The window already accepts a file-shaped interaction elsewhere: BU104 imports
  an audio file as a session (`src/audio/importer.py`,
  `UPLOAD_AUDIO_EXTENSIONS`). Follow its validation shape (extension allow-list,
  size check, graceful failure through `_on_status_update`) rather than
  inventing a second one.
- Qt drag-and-drop needs `setAcceptDrops(True)` plus `dragEnterEvent` /
  `dropEvent` on the detached `QDialog`. The window is a `QDialog` created with
  no parent, so the handlers go on it directly.

Tasks:
- Add `src/assistant/reference_doc.py`, Qt-free and network-free:
  - `ReferenceDoc` dataclass: `name`, `path`, `text`, `char_count`,
    `loaded_at`.
  - `load_reference_text(path, max_bytes) -> ReferenceDoc`: reads UTF-8 with a
    documented fallback for a file saved in the platform encoding, normalises
    line endings, rejects a file over the size cap, and raises a typed error
    rather than returning a half-loaded document.
  - `select_relevant_excerpt(doc, question, max_chars) -> str`: a long document
    cannot go into every prompt. Score paragraphs against the question's terms
    (the same whitespace-split AND-ish matching `FindController` already uses
    is enough — do not add an embedding dependency here) and return the best
    contiguous span under `max_chars`, with a deterministic tie-break so the
    same question always yields the same excerpt.
  - `build_reference_block(excerpt) -> str`: the labelled block appended to a
    question, distinct from the transcript block so the model can attribute.
- Config in `src/config.py`, under a `REFERENCE_DOC` block:
  - `max_bytes` (a size the prompt can never be blown up by),
  - `max_excerpt_chars`,
  - `allowed_extensions`: `[".txt"]` only.
- Drag and drop on the detached window:
  - `setAcceptDrops(True)`; `dragEnterEvent` accepts a single local file whose
    extension is allowed and **refuses everything else visibly** rather than
    silently ignoring it.
  - Dropping loads the file and attaches it to the window.
  - A themed drop affordance while a valid drag is over the window, in the
    pixel vocabulary — not Qt's default highlight.
- Attached-document UI in the answers rail header:
  - A chip showing the file name and size ("syllabus.txt · 12 KB") with a
    remove action; clicking it re-opens a file picker to replace the document.
  - Exactly one reference document at a time. A second drop replaces the first
    and says so through `_on_status_update`.
  - When none is attached, the header stays as BU115/BU116 left it — no empty
    placeholder chip.
- Wire into answering:
  - When a document is attached, the excerpt is appended to the question for
    both the manual and the candidate paths.
  - Transcripts mode gains the middle tier. Labels stay one short line each:
    `From transcripts:` / `From <filename>:` / `General knowledge:`.
  - General Knowledge mode ignores the attached document — it is an evidence
    mode, and this is evidence.
- Lifecycle: the document is held by the open detached window. Closing the
  window drops it; it is never persisted to `preferences.json` or the database,
  and a stale path is never re-read on reopen.
- Failure handling: an unreadable file, a file over `max_bytes`, a binary file
  with a `.txt` extension, or a permission error each surface through
  `_on_status_update` and leave any previously attached document intact.

Validation Requirements:

Required:
- executable behavior verified
- no syntax/runtime errors
- Definition of Done satisfied
- manual validation:
  - Drag a .txt onto the detached window and confirm the chip appears with the
    right name and size.
  - Ask (manually) something answered only by the document and confirm the
    answer comes back labelled `From <filename>:`.
  - Ask something answered by the transcript and confirm transcripts still win.
  - Ask something in neither and confirm the general-knowledge fallback.
  - Drag a .pdf and a folder and confirm both are refused with a visible
    message and no crash.
  - Drop a very large .txt and confirm it is refused by the size cap.
  - Remove the document and confirm answers go back to transcript-only.
  - Close and reopen the window and confirm no document is attached.

Tests Required:
- yes — `load_reference_text` (UTF-8, encoding fallback, oversize, missing
  file, binary content), `select_relevant_excerpt` (term matching, excerpt
  under the cap, deterministic tie-break, empty document, question matching
  nothing), extension validation, replace-on-second-drop, that closing the
  window releases the document, and that General Knowledge mode does not append
  the reference block

Out of Scope:
- Any format other than .txt (no PDF, .docx, .md)
- Indexing the document into RAG or the database
- More than one attached document at a time
- Persisting the attachment across window close or app restart
- Embedding-based excerpt selection
- Editing the document in the app

Definition of Done:
[ ] A .txt dropped on the detached window attaches and shows a named chip
[ ] Non-.txt drops and folders are refused visibly, with no crash
[ ] Oversize and unreadable files are refused and leave the previous document intact
[ ] An attached document is used as evidence in Transcripts mode, labelled by filename
[ ] Evidence order is transcript, then document, then general knowledge
[ ] General Knowledge mode ignores the attached document
[ ] Only one document at a time; a second drop replaces it
[ ] The document is released on window close and never persisted
