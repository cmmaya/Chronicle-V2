# BU162 — Diarization Runtime And Models

Status:
Completed

Goal:
Make sherpa-onnx and the two diarization models available to Chronicle,
in development and in the packaged build, without touching the
transcription runtime.

Context:
- Test of 2026-10-11 (DR session 2, Research Methods - Article Critique):
  sherpa-onnx with the pyannote segmentation-3.0 model and NeMo
  TitaNet-small embeddings separated the speakers correctly; the default
  WeSpeaker embedding over-split (19 speakers on a 2-speaker session).
- pyannote.audio is not an option: it needs PyTorch, which requirements.txt
  rules out, and a Hugging Face token for gated models.
- sherpa-onnx ships its own onnxruntime library. onnxruntime is pinned to
  1.20.1 because newer builds fail to load on some Windows / Python 3.12
  setups, so the two must be proven to load side by side.
- Models (k2-fsa GitHub releases), about 46 MB together:
  - sherpa-onnx-pyannote-segmentation-3-0 / model.onnx (5.99 MB)
  - nemo_en_titanet_small.onnx (40.3 MB)

- tests/test_bu162.py (new)

Tasks:
- Pin sherpa-onnx (exact version, verified in .venv312).
- Gate: in one process, import onnx_asr and load Parakeet, then import
  sherpa_onnx and build a diarizer (and the reverse order). If the two
  onnxruntime copies conflict, stop and report before going further.
- Add the diarization models to model_manager as an optional group: not
  part of the setup wizard's required download; fetched on first use with
  size checks, progress callback, cancel, and the same offline / disk-full
  errors as the required models.
- Bundle sherpa_onnx's native libraries in the PyInstaller spec.
