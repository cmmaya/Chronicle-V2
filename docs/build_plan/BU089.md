# BU089 — Session Router For Any Session

Status:
Completed

Goal:
Given a natural-language question, identify the handful of sessions it is about, out of a corpus that may hold 1000+ meetings, and build Any Session context from those sessions instead of dumping arbitrary chunks.

Context:
`AssistantSessionResolver.resolve` short-circuits on `explicit_scope == "any_session"` (src/assistant/session_resolver.py:106) and returns `ALL_SESSIONS` with no session ids, so the question never narrows anything. `_get_all_sessions_context` (src/assistant/service.py:389) then asks for 30 chunks and, because of the defect fixed in BU086, historically received the first 30 of 76 by rowid. Even with `MATCH` repaired, chunk-level lexical search alone will not reliably find the right meeting from a paraphrased question, and scanning all chunks does not scale. The fix is a two-tier design: route to sessions first using one compact profile vector per session, then only ever search chunks inside routed sessions. See docs/build_plan/ANY_SESSION_REFACTOR.md section 3.1.

Tasks:
- Add `src/rag/embeddings.py`: a lazily-loaded, singleton local embedding service producing 384-dimension float32 vectors, with `embed_passages(texts)`, `embed_query(text)`, an `is_available` flag, and a stable `model_id` property of the form `"<repo_id>@<revision>"`.
- Load the ONNX model directly with the already-installed `onnxruntime` (CPU provider) plus `tokenizers`. Do **not** add `fastembed`: it declares its own `onnxruntime` dependency and pip may promote it above the `onnxruntime==1.20.1` pin that requirements.txt:20-26 documents as the only version verified to import on Windows / Python 3.12, which would break Parakeet and therefore transcription.
- Add only `tokenizers` to requirements.txt. Do not change the `onnxruntime` pin. `huggingface-hub` is already available via `onnx-asr[cpu,hub]`.
- Use a multilingual model: meetings are recorded in Spanish and Parakeet v3 is multilingual, so an English-only encoder would cripple routing. Preferred `intfloat/multilingual-e5-small`; fallback `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`. Pin the repo id together with a revision, and download through the same Hugging Face hub pattern already used for Parakeet.
- Verify the ONNX artifact exists at the pinned revision before wiring it up. If neither repository ships one, export it once with `optimum` and vendor the result rather than exporting at runtime.
- Apply the model's required input prefixes inside the service, not at call sites, so query and passage encoding cannot drift apart. For E5 that means `query: ` and `passage: `.
- Mean-pool the last hidden state using the attention mask, then L2-normalise, so a dot product equals the cosine.
- The embedding service must report unavailability rather than raising, so callers can degrade to lexical-only.
- Add a `session_profiles` table: session_id, profile_text, keywords, embedding BLOB, embedding_model, content_hash, updated_at. Store vectors as float32 `.tobytes()`.
- Build the profile text per session from name, start date, the session summary, and keywords extracted from the summary.
- Add `src/rag/router.py` with `route_sessions(db, query, k=5) -> list[RoutedSession]`, scoring hybrid: normalised cosine between the query vector and the session profile matrix, blended with a normalised BM25 score from an FTS search over profile text and session name. Return session id, name, start time, score, and a short human-readable match reason.
- Load the profile matrix into memory once and cache it; invalidate the cache when profiles are written.
- Use brute-force numpy cosine. Do not add a vector database.
- When the embedding service is unavailable, `route_sessions` must still work using the lexical half alone.
- Rewrite `_get_all_sessions_context` to call `route_sessions`, then assemble context from the routed sessions' summaries plus a bounded number of their top chunks, keeping the existing 500-char per-excerpt and 12000-char total budgets.
- Return the routed candidates from the service so BU090 can surface them, without changing the existing `AnswerResponse` behaviour for other scopes.
- Keep the legacy fallback path reachable if routing yields nothing.
