# BU088 — Scope Mode Indicator And Specific Session Rename

Status:
Completed

Goal:
Rename the session-scoped mode to "Specific Session" and make the active scope mode visible and consistent everywhere in the UI.

Context:
`scope_combo` (src/app/window.py:2450) is currently the only working indicator of which scope is active. `_scope_label` (src/app/window.py:2507) is created with `setVisible(False)` and never shown, so the eight `_update_scope_label()` call sites do work that is discarded; worse, it renders the selected *session name* rather than the *mode*, conflating scope with selection. The detached assistant's scope combo (src/app/window.py:5135) syncs detached→main but not main→detached, so it can be read stale by `_on_detached_ask` (src/app/window.py:5276) and by the candidate retry path (src/app/window.py:5425). Nothing records which scope produced a given answer, so conversation history is ambiguous on scroll-back. See docs/build_plan/ANY_SESSION_REFACTOR.md section 2.5.

Allowed Files:
- src/app/window.py
- docs/current_state.md
- docs/devlog.md

Dependencies:
Required:
- none

Blocks:
- BU090

Tasks:
- Change the scope combo display text from "Current Session" to "Specific Session"; keep the item data value `"current"` unchanged.
- Keep `explicit_scope == "current_session"` as the internal wire value so `AssistantSessionResolver`, stored conversations, and existing tests continue to work. Do not rename internal keys.
- Repurpose `_scope_label` into a real mode indicator: make it visible, and have it show the active mode plus, when a session is selected, that session's name (for example `Specific Session — <name>` and `Any Session — all meetings`).
- Update `_update_scope_label` (src/app/window.py:4378) to read the mode from `scope_combo.currentData()` rather than deriving its text solely from `_selected_session_id`.
- Make the main→detached scope sync bidirectional so `_detached_scope_combo` can never be read stale; guard against signal recursion between the two combos.
- Update the ESC path `_clear_scope` (src/app/window.py:253) so the "Current Session" comment and behaviour read as "Specific Session", and avoid the duplicated transcript clear/reload caused by `setCurrentIndex` re-firing `_on_scope_changed`.
- Record the scope used on each assistant message and show it as a small, unobtrusive marker on the message bubble in `_add_message_to_conversation` (src/app/window.py:2800), so history stays legible.
- Sweep remaining user-facing occurrences of "Current Session" in labels, tooltips and placeholder text.
