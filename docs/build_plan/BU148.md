# BU148 — Session Documents Pop-Up From The All Sessions Menu

Status:
Completed

Goal:
A **Documents…** item in a session card's "•••" menu in All Sessions opens a
pixel-styled pop-up where the user drags files in or clicks **Import**, sees
the session's documents, previews the text the assistant will read, and
removes documents.

Context:
- The user chose the All Sessions card menu as the entry point
  (`_build_session_actions_menu`, `window.py` ~7655). It already hosts View
  summary / View screenshots / Rename, so Documents… sits with them.
- Documents can be added while a session is recording and after it ends
  (unlike Transcribe / Summarize, which are disabled while live), and to
  inserted-text sessions (`origin='text'`) too.
- Pop-up patterns to follow: `SettingsDialog` (`settings_dialog.py`) and
  `CalendarEventDialog` (`calendar_dialog.py`) for the pixel look;
  `DetachedTranscriptsDialog` (`window.py` ~292) + `PixelDropOverlay`
  (`pixel_widgets.py` ~2959) for drag-and-drop with a visible
  accept / refuse state.
- Background work: `session_manager.submit_job` + `_post_to_ui`, as the
  BU137 upload flow does, so a long PDF never freezes the window.
- BU146: `add_session_document` / `list_session_documents` /
  `get_session_documents` / `delete_session_document`; BU147:
  `extract_document`, `is_allowed_document`, `DocumentError`.

Tasks:
- Card menu: **Documents…** (or **Documents (N)…** when the session has
  any), placed after View screenshots, enabled for live and finished
  sessions alike. Opens the pop-up for that session.
- `SessionDocumentsDialog(QDialog)` in `src/app/documents_dialog.py`, modal to
  the All Sessions window, title "Documents — <session name>":
  - **Drop area** at the top: "Drag files here or Import" with the allowed
    types and limits listed ("txt, md, pdf, docx · up to 5 · 2 MB each").
    Uses the same accept (gold) / refuse (red) overlay states as the detached
    window; several files dropped at once are imported one by one.
  - **Import** button: `QFileDialog.getOpenFileNames`, filtered to the allowed
    extensions, remembering the last folder for the app session.
  - **List**: one row per document — name, type, size, character count,
    date added, and a remove (✕) button. Remove asks for confirmation (the
    text is not kept anywhere else).
  - **Preview**: selecting a row shows the stored extracted text, read-only,
    scrollable, so the user sees exactly what the assistant reads.
  - Empty state: the drop area plus "No documents yet. Answers for this
    session use only its transcript, summary and screenshots."
  - A footer line stating scope: "Used for this session's Specific Session
    questions and the transcripts window. Not used in Any Session."
- Import flow per file: row shows "Reading…" → background job runs
  `extract_document` then `add_session_document` → row becomes the document,
  or is removed and the error (`DocumentError` / limit / duplicate name) is
  shown in the dialog's status line. One bad file never stops the others.
- At the limit, the drop area and Import button are disabled with the reason
  shown.
- Signal `documents_changed(session_id)` emitted on every add / remove, and
  relayed by `MainWindow` as one signal so BU150 / BU151 can refresh their
  indicators. The All Sessions card refreshes its menu label.

Validation Requirements:

Required:
- executable behavior verified
- no syntax/runtime errors
- Definition of Done satisfied
- manual validation:
  - open Documents… on a finished session, drag a PDF and a .docx in, then
    Import a .md: three rows appear, previews show their text;
  - drag a .pptx and a folder: refused visibly, nothing added;
  - add a sixth document: refused with the limit message;
  - add a document to the session that is recording, without stopping it;
  - remove a document, reopen the dialog: it is gone; restart the app: the
    others are still there;
  - delete the session: its documents are gone (check the table).
- BU145 baseline tests still pass (nothing here touches prompts).

Tests Required:
- yes: `tests/test_bu148.py` (offscreen Qt, jobs run inline)
  - the menu has Documents… for live, finished and inserted sessions, with the

  - import of a valid file adds a row and emits `documents_changed`
  - a refused file shows its message and adds nothing; later files still import
  - limit reached disables import
  - remove asks, then deletes and emits `documents_changed`
  - preview shows the stored text
