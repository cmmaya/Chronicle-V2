# BU099 — In-Pane Find Bar (Ctrl+F) With Match Navigation

Status:
Completed

Goal:
`Ctrl+F` opens a small pixel-styled **find bar** floating at the top-right of the
**active pane** (BU098). It has a keyword field, a live `current / total` match
counter, ▲ / ▼ (previous / next) buttons, and closes on `Esc`. What it searches
depends on which pane is active:

- **left** — the *PAST CONVERSATIONS* sidebar list. Incremental keyword search
  over conversation titles **and** message bodies (`db.search_conversations`,
  BU097). ▲/▼ step through matching conversations; the current match is selected
  and scrolled into view; `Enter` loads it into the assistant panel
  (`_load_conversation`, BU097).
- **center** — the currently-loaded assistant conversation. Find-in-view over the
  message bubbles already in `_answer_layout`: ▲/▼ scroll the answers area to the
  next/previous matching bubble and highlight it. No DB call.
- **right** — the *TRANSCRIPTS WINDOW* stream. Same as center but over the
  bubbles in `_transcription_layout`.

Keywords are whitespace-split, AND-matched, case-insensitive — identical
semantics to BU097.

Context:
- BU098 provides `self._active_pane` (`"left" | "center" | "right"`), kept in
  sync with clicks and keyboard focus, and `PixelPanel.set_active`.
- BU097 provides `db.search_transcripts` (multi-keyword) and
  `db.search_conversations(query, limit)` plus the extracted
  `MainWindow._load_conversation(conv_id)` helper.
- Center bubbles: `_add_message_to_conversation` / `_replace_thinking_message`
  (`src/app/window.py:2941`, `:2986`) build each row with
  `aligned_bubble(text, ...)` and set `row.setProperty('role', ...)` and
  `row.setProperty('message_text', text)`. Rows live in `self._answer_layout`
  (a `QVBoxLayout`; last item is a stretch) inside `self._answer_scroll_area`
  (`src/app/window.py:2658`).
- Transcript bubbles: `add_transcription_to_view` (`src/app/window.py:2892`)
  builds each row with `aligned_bubble(display_text, ...)`, sets
  `row.setProperty('source', source)` and `row.setToolTip(timestamp)`. Rows live
  in `self._transcription_layout` inside `self._transcription_scroll_area`
  (`src/app/window.py:2876`); last item is a stretch. `display_text` is
  `"Mic: ..."` / `"System: ..."`.
- `aligned_bubble` (`src/app/pixel_widgets.py:503`) returns a row `QWidget`
  whose single non-stretch child is a `PixelBubble` (`:245`). `PixelBubble` has
  a custom `paintEvent` drawing a pixel-cut border (`CREAM_BORDER` /
  `BUBBLE_BLUE_BORDER`, 2px) — so highlight has to be a `PixelBubble` flag, not a
  stylesheet.
- Sidebar list: `self.conversations_list` (`QListWidget`, `src/app/window.py:2429`),
  each item's `Qt.UserRole` holds `conversation_id`; populated by
  `_load_past_conversations` (`src/app/window.py:485`).
- `QScrollArea.ensureWidgetVisible(widget, xmargin, ymargin)` is the scroll-to
  primitive for center/right.
- No `Ctrl+F` shortcut exists yet.

Tasks:
1. `PixelBubble` highlight flag (`src/app/pixel_widgets.py`):
   - Add `self._highlighted = False` + `set_highlighted(value: bool)` (repaint on
     change).
   - `paintEvent`: when highlighted, draw the border with `CREAM_BORDER` at 3px
     regardless of variant (a clear but non-garish "this is the current match"
     marker). Fill unchanged.
   - Helper `bubble_of_row(row: QWidget) -> PixelBubble | None` (find the
     `PixelBubble` child) so callers can highlight a row built by
     `aligned_bubble`.
2. `PixelFindBar` widget (`src/app/pixel_widgets.py`):
   - `QWidget` with pixel-cut navy background (reuse `pixel_round_rect_path` in
     `paintEvent`), ~330×46, `Courier New`.
   - Children: a cream `QLineEdit` (placeholder "Find…"), a `QLabel`
     (`"0 / 0"`), and two compact ▲ / ▼ buttons in the `PixelToolButton` visual
     idiom.
   - Signals: `query_changed(str)`, `next_match()`, `prev_match()`, `closed()`.
   - Key handling: `Esc` → `closed`; `Return` → `next_match`;
     `Shift+Return` → `prev_match`. `query_changed` fires debounced (~150 ms
     `QTimer`) on `textChanged`.
   - `set_match_count(current: int, total: int)` updates the label
     (`"0 / 0"` when `total == 0`) and enables/disables ▲/▼.
   - `focus_field()` selects all text and focuses the line edit.
   - Holds no search logic — purely UI + signals.
3. `FindController` (`src/app/window.py`, testable core):
   - Constructor takes callables injected by `MainWindow`:
     `search_conversations(terms) -> list[int]`,
     `list_center_texts() -> list[str]`, `list_right_texts() -> list[str]`
     (each returns the searchable text per row, in display order).
   - `parse_terms(query) -> list[str]` (whitespace split, lowercased, drop
     empties).
   - `set_mode(pane)`, `set_query(query)` → recomputes `self.matches`
     (list of indices for center/right, list of conversation ids for left) and
     resets `self.cursor` to `0` (or `-1` when empty).
   - `next() / prev()` advance `self.cursor` with wrap-around; return the current
     match handle or `None`.
   - `match_label() -> (current, total)` → `(cursor+1, len)` or `(0, 0)`.
   - Pure: no Qt, no DB — everything comes through the injected callables and
     plain lists. This is what `tests/test_bu099.py` exercises.
   - Matching rule (shared): a row matches when **every** term is a
     case-insensitive substring of its text.
4. `MainWindow` wiring (`src/app/window.py`):
   - One `self._find_bar = PixelFindBar(self)` (hidden initially) and
     `self._find = FindController(...)` with the three callables:
     - `search_conversations`: `[c["id"] for c in
       self.session_manager.db.search_conversations(" ".join(terms), limit=200)]`
       guarded by try/except → `logger.error`, return `[]`.
     - `list_center_texts`: walk `_answer_layout` rows (skip the stretch), read
       `row.property("message_text")`.
     - `list_right_texts`: walk `_transcription_layout` rows, read the bubble's
       label text (or a stored `row.property("find_text")` set in
       `add_transcription_to_view`).
   - `QShortcut(QKeySequence.Find, self)` → `_open_find_bar()`:
     - `pane = self._active_pane`; reparent `_find_bar` onto `self._panes[pane]`,
       position top-right with an ~8 px inset, `show()`, `raise_()`,
       `_find_bar.focus_field()`, `self._find.set_mode(pane)`, and re-run the
       current query.
     - A second `Ctrl+F` while open just calls `focus_field()`.
   - `_find_bar.query_changed` → `self._find.set_query(q)`; clear old highlight,
     apply highlight/selection for the new current match; push
     `set_match_count(*self._find.match_label())`.
   - `_find_bar.next_match` / `prev_match` → `self._find.next()/prev()`, then:
     - center/right: `bubble_of_row(row).set_highlighted(True)` on the new match
       (and `False` on the previous), `scroll_area.ensureWidgetVisible(row, 0, 40)`.
     - left: select the `conversations_list` item whose `Qt.UserRole == conv_id`
       and `scrollToItem`; if that id isn't in the list, remember it for `Enter`.
   - `Return` in the field with the **left** mode active loads the current match:
     `self._load_conversation(conv_id)` then close the bar.
   - `_find_bar.closed` (Esc / lost relevance) → clear every highlight, clear the
     list selection styling if added, `hide()`, return focus to the pane.
   - Reposition `_find_bar` on `resizeEvent` while visible; hide it if the active
     pane changes under it (simplest: close on `_set_active_pane` when the bar is
     open and the pane differs).
5. Keep the BU097 global **Search Chats** dialog and `session_search_input`
   untouched. No detached-window find bar.

  it uses the pixel UX (navy, cream field, Courier New, pixel-cut border).
- Closing the bar leaves no lingering highlight on any bubble and no leftover
  selection state.
- `db.search_conversations` failure is logged and shows `0 / 0`, never crashes.
- No regression to BU097's dialog, the assistant chat, the transcript stream, or
  BU098's pane highlighting.

Tests (`tests/test_bu099.py`, plain-Python, no Qt harness — drive `FindController`
with fake callables):
- `parse_terms("  Foo  BAR ")` → `["foo", "bar"]`; `""` / whitespace → `[]`.
- center mode: given fake texts, a single term selects the right indices in
  order; two terms AND; empty query → no matches, label `(0, 0)`.
- `next()` / `prev()` wrap around; `match_label()` tracks the cursor
  (`(1, 3)` → `(2, 3)` → `(3, 3)` → `(1, 3)`).
- right mode uses the right-texts callable; switching mode recomputes matches and
  resets the cursor.
- left mode returns the conversation-id list from the injected
  `search_conversations` callable, in that order; an empty result → `(0, 0)`.
- a `search_conversations` callable that raises is swallowed by the MainWindow
  adapter (test the adapter lambda in isolation if practical) — controller still
  yields `(0, 0)`.

Out of Scope:
- Highlighting *every* match at once (only the current match is marked) or
  in-text character highlighting inside a bubble.
- Find-and-replace, regex, quoted phrases, or field-scoped syntax.
- Jump-to-exact-message *inside* a conversation from left mode (it loads the
  whole conversation; stepping to the message within it can be a follow-on).
- A find bar in the detached assistant / transcripts windows.
- Searching across sessions or non-loaded conversations from center/right mode
  (that is BU097's dialog).
- Persisting the last query or a search history.
- Incrementally re-running left-mode search as new conversations arrive.
- Keyboard shortcut customisation.

Implementation Notes:
- `PixelBubble.set_highlighted` + `bubble_of_row` keep the highlight consistent
  for center and transcript rows (both come from `aligned_bubble`).
- `PixelFindBar` is dumb UI; `FindController` is the tested brain; `MainWindow`
  is the adapter that supplies row text, DB access, scrolling and highlighting.
- Left mode reuses `db.search_conversations` (BU097) and `_load_conversation`
  (BU097) — no new query.
- If left-mode conversation search grows (e.g. wanting to jump to the matching
  message inside the loaded conversation, or filtering the visible list), split
  that into **BU100** and keep BU099 to the find bar + center/right + basic
  left stepping.
- No schema change, no new module file (widgets go in `pixel_widgets.py`,
  controller in `window.py`).
