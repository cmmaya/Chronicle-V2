# BU102 — Resume Stopped Session From All Sessions

Status:
Completed

Goal:
Let the user resume recording into a previously stopped (or paused) session
from the "•••" actions menu on its card in the All Sessions window, continuing
into the same session_id instead of creating a new session.

Context:
The user asked for the ability to resume a session from the session window's
options. Pause/resume already existed for the currently active session
(BU060/BU061), but there was no way to pick a stopped session from All
Sessions and continue recording into it — transcripts, screenshots and
metadata must stay tied to the original session_id and start_time.

Allowed Files:
- src/app/session_manager.py
- src/app/window.py
- docs/build_plan/index.md
- docs/current_state.md
- docs/devlog.md

Dependencies:
Required:
- BU060

Blocks:
- none

Tasks:
- Add `SessionManager.resume_stopped_session(session_id)`: refuses if another
  session is currently active/paused, loads the target session via the
  existing `load_session`, flips its status back to active without touching
  `start_time`, sets it as `current_session`, and resumes recording.
- Add a "Resume" item to `_build_session_actions_menu` in
  `src/app/window.py`, shown for non-live sessions with status
  stopped/paused/completed, disabled with an explanatory label when another
  session is currently live.
- Wire the action to a new `_resume_session_from_all_sessions` handler that
  calls the manager method, updates the scope/selection UI to the resumed
  session, refreshes the All Sessions list, and closes the dialog.
