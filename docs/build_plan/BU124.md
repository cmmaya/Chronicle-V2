# BU124 — First-Run Setup Wizard Before The Main Window

Status:
Completed

Goal:
The first time Chronicle starts, and whenever something required is missing,
show a setup wizard instead of the main window. It chooses the data folder,
takes the API key and downloads the models with a progress bar. The main
window opens only after everything is in place.

Context:
- User requirement: models are downloaded after installation (the installer
  stays small), but the user must not see the app until setup has finished.
- `src/main.py` currently builds `MainWindow()` directly, and `MainWindow`
  opens the database and starts services in its constructor. The gate
  therefore has to sit in `main.py`, **before** `MainWindow` is imported,
  because importing it pulls in `onnx_asr` and `huggingface_hub`, and those
  must see `HF_HOME` / offline mode first.
- Building blocks: `paths` (BU121), `secrets` (BU122), `model_manager`
  (BU123).
- Setup is complete when all three hold: the data folder is resolved and
  writable, an API key is available, and `model_manager.status()` reports
  everything installed.

Design:
- `src/app/setup_wizard.py`, a `QWizard` styled with the existing pixel
  theme:
  1. **Welcome**: what will happen, the download size, and a note that
     recordings are processed locally but chat and summaries go to
     OpenRouter.
  2. **Data location**: defaults to `%LOCALAPPDATA%\Chronicle`, with a Browse
     button to pick any folder (for example a larger D: drive, since the
     models take several GB). Shows free space and required space. Refuses
     unwritable folders. Writes the BU121 pointer file.
  3. **API key**: field plus Test (BU122 `check_api_key`). Next is enabled
     only after a successful test. "Skip for now" is allowed, with a warning
     that chat and summaries will not work until a key is added.
  4. **Download models**: one progress bar per model plus overall MB/s and
     time left. The download runs on a `QThread`. Cancel, Retry and "Close and
     resume later" are available. Offline and disk-full errors show the
     BU123 messages.
  5. **Done**: Finish opens the main window.
- `main.py` flow: create `QApplication`, compute setup status, run the wizard
  if anything is missing (exit the app if the user closes it), apply
  `HF_HOME` / offline mode, then import and show `MainWindow`.
- Later launches with everything present go straight to the main window.
- Later launches with something missing (models deleted, data folder on a
  disconnected drive) reopen only the pages that are needed.
- The API key is the one exception: a skipped key does not block later
  launches. BU122 Settings covers adding it.

Tasks:

- "Close and resume later" keeps the partial files. The next launch reopens

- Running from source with a fully set-up machine never shows the wizard.
- Add a `--setup` command-line flag that forces the wizard open (for testing
  and repair).

Validation Requirements:

Required:
- executable behavior verified
- no syntax/runtime errors
- Definition of Done satisfied
- manual validation:
  - With an empty `CHRONICLE_DATA_DIR` and no key: the wizard appears, no main
    window is shown, all pages complete, and the main window opens and
    records with live transcription straight away (no second download).
  - Choose a custom folder on another drive and confirm the database, sessions
    and models all land there.
  - Close the wizard mid-download, relaunch, and confirm it resumes on the
    download page.
  - Delete one model file, relaunch, and confirm only the download page
    reappears.
  - Skip the key, then confirm the app opens, chat explains that a key is
    needed, and adding it in Settings fixes it.

Tests Required:
- yes — the gate decision (which pages are needed for each combination of
  missing pieces); the wizard is not shown when complete; the data-location
  page rejects unwritable and too-small folders; the download page handles
  cancel and error with the manager mocked (`pytest-qt` or direct slot calls)

- Moving an existing data folder
- Auto-updates
