# BU103 — Grouped Live Transcript Bubbles

Status:
Completed

Goal:
Redesign the live transcript stream so it reads like a fluid conversation
(Teams-style) instead of a new bubble stacking up every ~10 seconds: stack
consecutive same-source chunks into one growing bubble, show a single
`HH:MM` timestamp per bubble instead of per chunk, and give appended text a
brief fade-in — all without changing the pixel UI's colors/fonts/layout and
without adding any new audio/transcription computation.

Context:
The user finds the transcript panel choppy: every ~10-second audio chunk
(`ChunkedAudioRecorder.CHUNK_DURATION` in
[src/audio_capture/core.py](../../src/audio_capture/core.py)) currently
produces its own bubble via `add_transcription_to_view`
([src/app/window.py](../../src/app/window.py)), so a single continuous
sentence gets sliced into several stacked bubbles with no visible time. They
asked for: (1) bubbles that keep stacking through roughly a minute of
continuous talk, (2) a bubble to end when there's an actual pause - using
the VAD check that's already in place - and (3) a visible `HH:MM` time
(their example: `21:03`) shown once per bubble instead of once per chunk,
plus (4) a light fade/slide-in when new text lands, for extra fluidity.

Design decision (flagged for confirmation): the user described the pause
signal as "VAD ratio <= 20%". The existing VAD check
(`ChunkedAudioRecorder._check_vad` in `core.py`) already discards any chunk
below the configured speech-ratio threshold (default 30%, adjustable in
Settings > VAD Settings) *before* it ever reaches the live-transcription
callback - so a chunk failing that check never arrives at the UI at all.
Rather than plumbing the raw ratio through `live.py` /
`session_manager.py` / `window.py` just to re-derive the same fact, this BU
detects a pause from the existing gap between one chunk's `timestamp_end`
and the next chunk's `timestamp_start` for the same source (both already
carried on every live-transcription result) - a gap bigger than roughly one
missed chunk means the VAD check silently dropped that window, which *is*
the pause. Same outcome, no new computation, no cross-file plumbing. If the
user wants the literal ratio surfaced instead, that's a separate follow-up.

Tasks:
- `pixel_widgets.py`: relax `_SCOPE_FOOTER_RE` from matching only
  `"\n\n(— via .+)$"` to matching any `"\n\n(— .+)$"` suffix, so the same
  small italic muted footer `PixelBubble` already renders for scope tags
  (e.g. "— via Any Session") can also render a timestamp caption (e.g.
  "— 21:03") without introducing new styling.
- `pixel_widgets.py`: add `PixelBubble.append_text(text)` - appends
  `" " + text` to the stored `_body_text` and re-renders `self.label`
  through the same path `set_match_terms` already uses (plain markdown, or
  re-applying active highlight terms), so BU099 find-highlighting keeps
  working on grown bubbles.
- `window.py`: track one "open group" per source (`mic` / `system`) - the
  row widget, its `PixelBubble`, the group's start time, and the last
  chunk's end time. Reset this alongside `_transcription_history` in
  `_clear_transcription_view`.
- `window.py`: stop collapsing live results into a pre-formatted string for
  `_append_transcription` (the current `QMetaObject.invokeMethod` /
  `Q_ARG(str, ...)` / regex-reparse round trip loses `timestamp_end`).
  Carry `text`, `source`, `timestamp_start`, `timestamp_end` through the
  thread-safe hop instead.
- `window.py`: rework `add_transcription_to_view` to decide, per source,
  whether to start a new bubble or extend the open one:
  - No open group yet, the source changed, the gap between the open
    group's `last_end` and the new chunk's `timestamp_start` exceeds a
    `TRANSCRIPT_PAUSE_GAP_SECONDS` constant (~1.5x chunk duration), or the
    open group has already run for `TRANSCRIPT_MAX_GROUP_SECONDS` (~60s) ->
    start a new bubble exactly as today, with a footer of `"— HH:MM"` (the
    group's start time) appended to the bubble text via the relaxed footer
    regex.
  - Otherwise -> call `bubble.append_text(text)` on the open group's
    bubble, update the row's `find_text` property to the merged text (so
    BU099's find bar and BU101's download still see the full text), and
    update the group's `last_end`.
  - Mic and system chunks never merge into each other (separate open-group
    slots, separate alignment/variant as today).
- `window.py`: play a short (~150-250ms) opacity fade via
  `QGraphicsOpacityEffect` + `QPropertyAnimation` on the row whenever it is
  first inserted or newly extended, so both new bubbles and appended text
  register as a small "live" transition. Keep one effect/animation per row
  (no accumulating animations on repeated appends).
- `window.py`: point the historical-transcript load path (the loop that
  currently calls `add_transcription_to_view(text, source, time_str)` when
  opening a past session) at the same grouped call, passing each row's
  timestamp, so reloaded sessions render with the same grouped bubbles and
  once-per-group timestamps instead of one bubble per stored transcript
  row. `_transcription_history` (used by the transcript download button,
  BU101) keeps logging one full `[HH:MM:SS] Source: text` line per raw
  chunk regardless of visual grouping, so downloads stay at full
  resolution.

Out of Scope:
- Surfacing the raw VAD speech-ratio value anywhere (see Design decision
  above) - only the chunk-gap heuristic is implemented
- Any change to `ChunkedAudioRecorder` / VAD thresholds / chunk duration in
  `src/audio_capture/core.py` - transcription cadence and compute cost are
  unchanged
- User-facing settings for the pause-gap or max-group-duration constants -
  fixed constants for now
- The detached transcript window (`_add_transcription_to_detached`) - keeps
  its current flat per-chunk line format
- Any change to how transcripts are stored in the database

Definition of Done:
[ ] Consecutive same-source chunks with no real pause render as one growing
    bubble instead of a new bubble per chunk
[ ] A bubble ends and a new one starts on: source change, a chunk-arrival
    gap consistent with a VAD-dropped (silent) window, or ~60s of
    continuous grouped talk
[ ] Each bubble shows exactly one `HH:MM` timestamp (the group's start
    time), styled with the existing muted footer look - no new colors/fonts
[ ] Newly inserted or newly extended bubbles play a brief fade-in
[ ] Historical session reload uses the same grouped rendering
[ ] BU099 find bar and BU101 transcript download both still work correctly
    against grouped bubbles
