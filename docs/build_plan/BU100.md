# BU100 — Collapsible Sectioned Summary View

Status:
Completed

Goal:
Replace the current flat, plain-text summary dialog with a themed view where each summary section (Overview, Key Points, Action Items, Decisions, Next Steps/Open Questions) is its own collapsible panel the user can expand or collapse independently.

Context:
The user asked to enhance the summary window: identify the current one, then make it more aesthetic and let sections be deployed/undeployed individually. Today, `src/app/window.py` has three near-duplicate methods (`_show_session_summary`, `_show_summary_by_session_id`, `_on_view_summary_icon_clicked`) that each build a `QDialog` with a plain `QTextBrowser.setPlainText(summary_content)` — no parsing, no structure, no styling beyond a gray info label. The stored summary content (from `SummaryGenerator`, template `TemplateType.FULL` or `GENERAL_TRANSCRIPT`) is plain text with numbered section headers such as `1. Overview`, `2. Key Points`, `3. Action Items`, `4. Decisions` / `4. Decisions Made`, `5. Open Questions or Unclear Points` / `5. Next Steps`. The app already has a themed widget module (`src/app/pixel_widgets.py`) with an established navy/cream palette used elsewhere in the UI, which this view should match.

Tasks:
- In `src/app/pixel_widgets.py`, add a `CollapsibleSection` widget: a header bar showing the section title and an expand/collapse indicator (e.g. chevron/toggle button), and a content area that shows/hides on click. Style it with the existing NAVY/CREAM/BORDER_BLUE palette already defined in that file so it matches the rest of the app.
- Add a small parser (in `window.py` or `pixel_widgets.py`) that splits a raw summary string into an ordered list of `(title, body)` sections based on the numbered headers produced by the FULL and GENERAL_TRANSCRIPT templates (`Overview`, `Key Points`, `Action Items`, `Decisions` / `Decisions Made`, `Open Questions or Unclear Points` / `Next Steps`). Drop the model's lead-in text before the first recognized header ("Here's a comprehensive summary of the meeting:") - it is chatter, not a section. If no recognized headers are found at all, fall back to a single section (e.g. "Summary") containing the whole text, so unexpected/legacy content still displays.
- Body formatting rules: render markdown `**bold**` as `<b>` (regex applied after HTML escaping) against a normal-weight base font so emphasis reads by contrast; align body text left with the block vertically centred in its card; keep secondary metadata (type / model / date) separated from the body in its own smaller, muted label.
- Add one shared dialog-building method (e.g. `_build_summary_dialog(session_id, session_name)`) that fetches the summary, parses it into sections, and renders one `CollapsibleSection` per section inside a scroll area, replacing the single `QTextBrowser`. Keep the existing header (session name) and type/model info label.
- All sections start expanded when the dialog opens; each can be collapsed/expanded independently by the user via its header.
- Replace the bodies of `_show_session_summary`, `_show_summary_by_session_id`, and `_on_view_summary_icon_clicked` so all three call the shared builder instead of duplicating dialog-construction code. Preserve each call site's existing "no summary" guard/messaging behavior.
- Support multiple scales of the window: the dialog is freely resizable (size grip + maximize) and carries a text-scale stepper (A- / A+ with a percent readout, Ctrl+- / Ctrl++ / Ctrl+0) that scales every font in the view. Remember the chosen scale and the window size for the rest of the app session.
