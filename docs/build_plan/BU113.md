# BU113 — Manual Chunk Selection And Answer From Context Menu

Status:
Pending

Goal:
Let the user select one or more transcript bubbles in the detached window,
right-click, and get an answer in the left rail from the same assistant agent
the chat panel uses.

Context:
- This is the manual half of the feature and is deliberately built before any
  automatic detection. A measured bake-off on session 46 ("Class 1 - RM P2")
  showed cheap detectors mark rhetorical questions as answerable 2-13 times
  per session, so the user-driven path is the one that is correct by
  construction.
- Answering must reuse the existing chat agent, not a parallel prompt:
  `self.assistant_service` (`AssistantAnswerService`), the agent chosen in
  `self.agent_combo`, and `get_selected_model()`. `AssistantQueryThread`
  already runs `ask()` off the Qt thread and is the pattern to follow.
- Scope is always the session being viewed, so the call passes
  `explicit_scope="current_session"` with that session id. The router,
  scope-offer and handoff paths (BU089-BU093) are not involved.
- BU111 put `record_indices` on each bubble row; that is how a selection maps
  back to chunk text.
- A right-click context menu already exists for `conversations_list`
  (`setContextMenuPolicy(Qt.CustomContextMenu)`); reuse that pattern and the
  existing `QMenu` stylesheet used by the filter menus.

Tasks:
- Selection model on transcript bubbles:
  - Click selects a bubble; Ctrl+click toggles one; Shift+click selects the
    contiguous range from the anchor. Esc or a click on empty space clears.
  - Selected rows get a themed selected state (border/background shift
    consistent with the pixel theme, readable in both bubble variants).
    Keep it visually distinct from the BU103 fade and from filter-hidden rows.
  - Selection survives a filter change only for rows still visible; hidden
    rows drop out of the selection.
- Context menu on right-click over the transcript column:
  - "Answer question" (enabled when >=1 bubble is selected; if the
    right-click lands on an unselected bubble, select it first, matching
    normal list behavior).
  - "Copy text", and "Clear selection".
  - Menu uses the existing `QMenu` stylesheet from `_show_detached_filter_menu`.
- Add `src/assistant/live_qa.py` with a pure
  `build_question_from_records(records) -> str`: joins the selected chunks in
  timestamp order, prefixes each with its source label and `HH:MM:SS`, and
  collapses the chunk-overlap duplication the recorder produces (consecutive
  chunks repeat their leading words). No network calls in this module for
  this BU.
- Wire the action:
  - Build the question text, post a "pending" answer card into the left rail
    immediately (question text + timestamp range + spinner/"Thinking...").
  - Run `AssistantQueryThread` with the current `agent_combo` agent,
    `explicit_scope="current_session"`, and the viewed session id.
  - On success replace the card body with the answer, rendered through the
    existing `simple_markdown_to_html` path so it matches chat styling.
  - On error show a themed failure state in the card with a "Retry" action.
- Answer cards: newest at the top, each collapsible
  (`PixelCollapsibleSection` where it fits), showing the source timestamp
  range, and dismissible. Clicking a card's timestamp scrolls the transcript
  column to the originating bubble and flashes it.
- Concurrency: more than one answer may be in flight. Key each card to its
  own thread and card id; do not reuse the single `_assistant_thread` slot
  the chat panel uses, and do not let a detached answer disable the chat
  Ask button.

Validation Requirements:

Required:
- executable behavior verified
- no syntax/runtime errors
- Definition of Done satisfied
- manual validation:
  - Select one bubble, right-click, "Answer question", and confirm an answer
    card appears left and the chat panel is unaffected.
  - Ctrl+click three non-adjacent bubbles and Shift+click a range; confirm
    the question sent contains exactly the selected chunks in time order.
  - Fire two answers in quick succession and confirm both resolve into their
    own cards.
  - Switch the agent in the chat panel and confirm the next answer uses it.
  - Click a card's timestamp and confirm the transcript scrolls to the right
    bubble.

Tests Required:
- yes - `build_question_from_records` (ordering, source labels, overlap
  collapsing, single vs multi record), selection range math (ctrl/shift/
  anchor, hidden-row exclusion), card-to-thread keying so two in-flight
  answers cannot cross-populate

- Auto mode, detector model picker, window-size control (BU115)
- Persisting answers to the database or assistant_conversations
- Changing the chat panel's own ask flow
- Answering across sessions (scope is always the viewed session)

[ ] One or many bubbles can be selected with click / Ctrl+click / Shift+click
[ ] Right-click offers "Answer question" and it is enabled only with a selection
[ ] The question is assembled from the selected chunks in time order, overlap collapsed
[ ] Answers come from the same agent and model as the chat panel
[ ] Answer cards appear in the left rail, newest first, dismissible, with a working retry
[ ] Two concurrent answers resolve independently and never populate the wrong card
[ ] Clicking a card's timestamp scrolls to the originating bubble
