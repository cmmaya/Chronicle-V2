# BU115 — Auto Mode Controls And Detected-Question Cards

Status:
Completed

Goal:
Wire the BU114 detector into the detached window: an auto/manual mode toggle,
a 1-5 chunk detection-window control, a detector model picker, and detected
questions surfaced as cards in the left rail that answer with one click.

Context:
- BU113 gave the left rail manual answer cards. This BU adds a second card
  kind - a *candidate* - which shows a detected question and an "Answer"
  action, and becomes a normal answer card once answered.
- Measured precision is why candidates default to one-click rather than
  auto-answering. On session 46 the best detector (`gemini-3.8-flash`) was
  clean, but on a sample of 3 meeting-mode positives from one lecture; the
  cheap detectors were not. So auto mode ships with "Suggest only" as the
  default and "Answer automatically" as an explicit opt-in. Flipping that
  default is a decision for after multi-session validation, not a code change
  buried here.
- The detector model is chosen here and is separate from the answering model:
  answers always use the global chat agent and `get_selected_model()`, per
  the user's requirement. Two distinct pickers, clearly labelled.
- Existing theme vocabulary for controls: `PixelToolButton`,
  `pixel_filter_chip`, `PixelStatusChip`, the styled `QMenu` used by the
  filter menus, and `PixelCollapsibleSection` for card bodies.

Tasks:
- Header controls in the detached window's left (answers) column:
  - Mode toggle: "Manual | Auto". Manual is the default and disables the
    detector entirely - no calls, no spend.
  - Detection window control, 1-5 chunks, labelled with what it means in
    time (chunks are ~5 s each, so "3 chunks (~15 s)"). Writes
    `LIVE_QA.window_chunks`.
  - Detector model picker listing exactly the three BU114 models, each with
    its short cost/accuracy note so the tradeoff is visible at the point of
    choice. Default `gemini-3.8-flash`.
  - Auto-mode sub-option "Answer automatically" (default off). When off,
    candidates wait for a click; when on, a candidate above `min_confidence`
    is answered immediately.
  - A spend chip showing this session's detector calls and accumulated cost,
    fed by BU114's counters.
- Candidate cards in the left rail:
  - Show the detected question text, `HH:MM:SS`, asker (Mic/System), and the
    detector's `kind`. Actions: "Answer", "Dismiss".
  - Only candidates passing the mode policy are shown: genuine + answerable,
    plus `directed_at_user` when the user has chosen meeting-style filtering.
    Rhetorical and discourse candidates are never surfaced.
  - Clicking "Answer" runs the *same* BU113 answer path - global agent,
    `explicit_scope="current_session"` - and the card becomes an answer card
    in place.
  - Clicking the card's timestamp scrolls the transcript column to the
    originating bubbles and flashes them (BU113 behavior, reused).
- Feed the detector: `_on_live_transcription` passes each new
  `TranscriptRecord` to the `QuestionDetector` when auto mode is on and a
  session is live. Detection stops on pause, stop, and window close.
- Lifecycle and safety:
  - Switching to Manual, closing the detached window, or stopping the session
    tears the detector down and releases its thread.
  - Changing the detector model or window size takes effect on the next
    detection without restarting the session.
  - Honour `max_detections_per_session`; when reached, show a themed notice
    in the rail rather than silently stopping.
- Persist mode, window size, detector model, and the auto-answer sub-option
  in `preferences.json` alongside the BU112 layout state.

Validation Requirements:

Required:
- executable behavior verified
- no syntax/runtime errors
- Definition of Done satisfied
- manual validation:
  - Record a session in Auto mode and confirm candidate cards appear for real
    questions, that "any questions?" never appears, and that the spend chip
    increments.
  - Click "Answer" on a candidate and confirm the answer uses the agent
    selected in the chat panel, not the detector model.
  - Switch to Manual mid-session and confirm no further detector calls are
    made (spend chip stops moving).
  - Change the detection window from 3 to 5 chunks and confirm the next
    detection uses the wider context.
  - Enable "Answer automatically" and confirm a high-confidence candidate
    answers without a click.
  - Close the detached window mid-session and confirm the detector thread is
    released and recording continues.

Tests Required:
- yes - mode policy filter (genuine/rhetorical/discourse x directed_at_user),
  preference round-trip for all four settings, detector teardown on
  manual/close/stop, `max_detections_per_session` cap behavior, and that the
  answer path uses the chat agent id rather than `LIVE_QA.detector_model`

Out of Scope:
- Persisting detections or answers to the database
- Multi-session detector validation (a separate measurement task, not a BU)
- A settings window for `LIVE_QA` beyond the in-window controls
- Class-vs-meeting as a full product mode - here it is only the
  `directed_at_user` filter toggle
- Changing the default away from "Suggest only"
