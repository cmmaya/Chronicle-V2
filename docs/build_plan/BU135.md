# BU135 — Text Transcript File Parser

Status:
Completed

Goal:
A pure function that reads a user-picked transcript file and returns clean
paragraphs ready to store, or raises a readable error.

Context:
- `src/audio/importer.py` is the audio counterpart: it decodes a file and
  exposes `SUPPORTED_EXTENSIONS` for the file dialog filter. This BU mirrors
  that shape for text so the UI (BU137) can reuse the same pattern.
- Transcripts exported from other tools (Teams, Zoom, Otter, Chronicle's own
  download) are usually `.txt`, often UTF-8 with a BOM, sometimes cp1252.
- The screenshot the user shared shows the text split into paragraphs, with a
  blank line between them, inside one bubble.

Decisions:
- `SUPPORTED_EXTENSIONS = ('.txt', '.md')`.
- Decoding order: `utf-8-sig`, then `cp1252`. A NUL byte in the first 4 KB →
  "not a text file".
- Size cap: 2 MB (a ~5 h meeting is well under that). Larger → a readable
  error.
- Paragraphs = blocks separated by one or more blank lines. Inside a block,
  single newlines are kept (speaker lines stay on their own line). Trailing
  whitespace stripped, `\r\n` normalized to `\n`.
- The text is stored as-is: no speaker parsing, no timestamp parsing.
