# BU116 — Concise Answers And Two Answer Modes

Status:
Completed

Goal:
Make live answers short and useful: fix the auto-mode path that currently sends
the transcript window without the question it detected, rewrite the agent
instructions so answers are terse, and add two explicit answer modes —
Transcripts (evidence first, general knowledge only as a labelled fallback) and
General Knowledge (answer directly).

Context:
- **Auto mode does not answer properly, and the cause is known.**
  `_answer_candidate` (`src/app/window.py`) builds its question with
  `build_question_from_records(records)`, where `records` are the chunks in the
  detector's rolling window. That function emits `QUESTION_PREAMBLE`
  ("Answer the question in the following transcript excerpt...") followed by
  the raw transcript lines. **`candidate.text` — the question the detector
  actually identified — is never sent.** The model receives an excerpt and has
  to re-find the question itself, which is the detection work being paid for
  twice and thrown away once. Manual selection has the same shape but the user
  chose the chunks, so the intent is implicit; a detected candidate has an
  explicit question and must carry it.
- Answers are verbose because they run the chat panel's agent, whose
  `system_instruction` is written for a chat pane. `research_helper` (the
  default) says "Clearly indicate when you're using general knowledge vs
  transcript content" — a paragraph-shaped instruction rendered into a ~440 px
  card that wants one or two sentences.
- The two modes the user asked for:
  - **Transcripts** — check the session evidence first. If it answers, reply
    from it. If it does not, say so in one short line and then give a concise
    general-knowledge answer, clearly labelled.
  - **General Knowledge** — answer directly, concisely, no evidence check.
- This is a separate axis from the BU115 detection modes (Manual / Suggest /
  Auto), which decide *whether and when* to answer. The answer mode decides
  *how*. Two controls, and the BU115 chips already establish where mode
  controls live in the answers rail.
- Existing vocabulary to reuse: `ASSISTANT_AGENTS` and `LIVE_QA` in
  `src/config.py`, `AssistantAnswerService.ask_async`, `AssistantQueryThread`,
  `build_question_from_records` / `QUESTION_PREAMBLE` in
  `src/assistant/live_qa.py`, `pixel_filter_chip` and `PixelAnswerCard` in
  `src/app/pixel_widgets.py`, `_update_preferences` for persistence.

Tasks:
- Fix the auto-answer question (the bug above):
  - Add `build_question_for_candidate(candidate, records) -> str` to
    `src/assistant/live_qa.py`: states the detected question explicitly, then
    supplies the surrounding chunks as context, clearly separated so the model
    cannot mistake context for the question.
  - `_answer_candidate` uses it. `_on_answer_selected_chunks` (manual) keeps
    `build_question_from_records`, which stays as-is for that path.
  - A candidate whose `record_indices` no longer resolve still asks
    `candidate.text` alone rather than falling through to an empty question.
- Answer-mode setting:
  - `LIVE_QA["answer_mode"]`, default `"transcripts"`, values
    `"transcripts"` / `"general"`.
  - Two chips in the answers-rail header, alongside the BU115 detection chips
    but visibly a separate group (label or separator — they answer different
    questions and must not read as one five-way control).
  - Persisted in `preferences.json` as `live_qa_answer_mode`, validated on
    load the way `normalize_live_qa_mode` validates its own.
- Answer prompts, in `src/config.py` so they are tunable without code:
  - `LIVE_QA["answer_instructions"]`, one per mode.
  - **Transcripts**: answer from the session evidence when it is there. When it
    is not, reply exactly:
    ```
    From transcripts: No answer found
    General knowledge: <concise answer>
    ```
    When it is there, reply `From transcripts: <concise answer>`.
  - **General Knowledge**: a concise answer, no prefix, no evidence check.
  - Both: answer in at most ~2 sentences unless the question genuinely needs a
    short list; no preamble, no restating the question, no hedging about being
    an AI. Put the length rule in the prompt, not only in the docs.
- Route the instruction: the live answer call must use the mode's instruction
  rather than the chat agent's `system_instruction`, while still using the
  agent's **model** and `get_selected_model()` per BU113. Decide and document
  where this override enters (`AssistantQueryThread` argument, or a dedicated
  `system_instruction` parameter on the service call) without changing the chat
  panel's own ask flow.
- Rendering: `PixelAnswerCard` shows the `From transcripts:` /
  `General knowledge:` labels as distinct lines, not as body prose — the label
  is what tells the user how far to trust the answer, so it must survive
  `simple_markdown_to_html`.
- Keep answer length honest in the UI: a card that is now one or two sentences
  should not reserve the height it did for a paragraph.
