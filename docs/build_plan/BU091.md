# BU091 — Embedding Backfill And Incremental Reindex

Status:
Completed

Goal:
Bring existing sessions into the new chunking and embedding scheme, and keep chunks, embeddings, session profiles and the FTS index in sync as sessions are recorded and summarised.

Context:
BU087 changes how transcripts are chunked and BU089 introduces per-session profile vectors, but neither backfills the corpus that already exists. Live data at the time of writing holds 39 sessions and 836 transcripts producing only 38 `rag_documents` and 76 `rag_chunks`, so coverage is already incomplete. Indexing is currently triggered from `session_manager.py:389`, `session_manager.py:451`, `session_manager.py:589` and `window.py:659`; those hooks must also refresh embeddings and profiles. Without this BU, Any Session routing has almost nothing to route over. See docs/build_plan/ANY_SESSION_REFACTOR.md section 3.4 and decision 10.

Tasks:
- Add a one-time backfill that re-chunks every existing session under the BU087 scheme, computes chunk embeddings, builds session profiles with their vectors, and rebuilds the FTS index.
- Run the backfill on a background thread with progress reported to the status bar. It must not block application launch.
- Make the backfill idempotent and resumable via content hashes, so an interrupted run can be re-entered safely and an unchanged session is skipped.
- Record the embedding model id and revision (`"<repo_id>@<revision>"`) alongside every stored vector, and treat a change of either as invalidation so vectors are recomputed rather than silently mixed across models.
- Extend the existing index hooks so that stopping a session, completing transcription, and regenerating a summary all refresh chunks, chunk embeddings, the session profile and the FTS index together.
- Ensure `replace_rag_chunks` and `rebuild_rag_fts` keep embeddings and FTS consistent with each other; a rebuild must not orphan or drop vectors.
- Add a user-triggered "Reindex all" action so a corrupted or stale index can be rebuilt without editing the database by hand.
- If the embedding service is unavailable, complete the lexical portion of indexing, skip vectors, log clearly, and leave the corpus in a state a later run can repair.
