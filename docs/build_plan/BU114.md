# BU114 — Question Detection Service

Status:
Completed

Goal:
Add a background question-detection service that watches the live transcript,
classifies candidate questions with a selectable detector model, and emits
de-duplicated candidates. No UI and no auto-answering in this BU.

Context:
- Measured on session 46 ("Class 1 - RM P2", 188 chunks, 2h08m) against 21
  hand-labeled question-like utterances. Detector accuracy differs sharply by
  model, and not along the price curve:

  | model | rhetorical wrongly called genuine | wrongly answerable | dups | $/session |
  | --- | --- | --- | --- | --- |
  | google/gemini-3.8-flash | 0/6 | 0/11 | 1/19 | $0.188 |
  | qwen/qwen3-14b | 3/5 | 2/13 | 8/31 | $0.033 |
  | google/gemini-2.5-flash | 6/7 | 5/28 | 27/44 | $0.038 |
  | google/gemma-3-12b-it | 13/13 | 7/41 | 43/80 | $0.006 |
  | google/gemini-2.5-flash-lite | 1/3 | 0/31 | 31/53 | $0.012 |

  `gemini-3.8-flash` missed none of the 21 ground-truth questions and produced
  zero false "answerable" calls; `qwen3-14b` is the best cheap option;
  `2.5-flash` and `flash-lite` are not worth offering. Hence the three
  detectors the user asked for: cheap (`qwen3-14b`), `2.5-flash` (included on
  request, documented as the weak middle), and `3.8-flash` (default).
- Discourse detection ("any questions?", "any answers?") was correct in every
  model tested, so a local blocklist handles that tier with no model call.
- Cost scales with transcript events, not wall-clock: session rates in the
  database range from 1.5 to 15.4 events/min, so a busy meeting can cost ~9x
  a lecture at per-chunk cadence. A time-based cap is what makes spend
  predictable, and it also structurally reduces the duplicate firings that
  per-chunk detection produces on overlapping windows.
- Detection must never touch the Qt thread or the recording pipeline. Follow
  the `src/transcription/worker.py` pattern; BU105 reworked threading and
  memory, and this service must not regress it.

Tasks:
- Add a `LIVE_QA` block to `src/config.py`:
  - `detector_model`: default `"google/gemini-3.8-flash"`.
  - `detector_models`: the three offered ids, each with a label and a short
    cost/accuracy note for the UI (BU115) to render.
  - `window_chunks`: 3, valid range 1-5 - how many transcript chunks of
    context the detector sees.
  - `min_detect_interval_seconds`: 15 - the spend cap; at most one detector
    call per interval no matter how fast chunks arrive.
  - `min_confidence`: 0.8, `max_detections_per_session`: 40.
  - `discourse_blocklist`: the filler phrases suppressed locally.
- Extend `src/assistant/live_qa.py` (created in BU113) with:
  - `DetectedQuestion` dataclass: `text`, `asker`, `kind`
    (genuine|rhetorical|discourse|request), `directed_at_user`, `answerable`,
    `confidence`, `record_indices`, `detected_at`.
  - `local_gate(window_text) -> bool`: free interrogative pre-filter. Measured
    at 37% pass rate on session 46; it exists to cut calls and latency, and
    must never be the only thing deciding a question is absent.
  - `is_discourse(text) -> bool`: blocklist check, applied before any call.
  - `DETECTOR_SYSTEM_PROMPT`: emits neutral labels only (`kind`,
    `directed_at_user`, `answerable`). Class-vs-meeting policy is a local
    filter applied by the caller, not a second prompt - one call serves both.
  - `parse_detection(raw) -> list[DetectedQuestion]`: strict JSON parse,
    tolerant of a markdown fence, returning `[]` on malformed output rather
    than raising.
  - `dedupe(candidate, seen) -> bool`: normalized-text match against a
    session-global set that never expires. Measured: duplicates are
    overwhelmingly exact repeats, and a non-expiring set is also what catches
    a stale question resurfacing 40 s later.
- `QuestionDetector` service class:
  - Fed `TranscriptRecord`s; maintains a rolling window of the last
    `window_chunks` records.
  - Enforces `min_detect_interval_seconds`, the local gate, and the discourse
    blocklist before spending a call.
  - Calls OpenRouter through `OpenRouterClient` with `temperature=0` and the
    configured detector model - independent of `get_selected_model()`, which
    stays the answering model.
  - Runs on its own worker thread; emits candidates through a callback.
    Never blocks the caller, never raises into the transcription path.
  - Tracks per-session call count and accumulated cost, exposed for the
    BU115 spend counter. Stops detecting at `max_detections_per_session`.
- Failure handling: a network error, a rate limit, or malformed JSON is
  logged and skipped. Detection is best-effort and must never interrupt
  recording, transcription, or the UI.
