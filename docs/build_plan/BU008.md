# BU008 — Refactor Audio Capture for Dual Sources

Status:
Pending

Goal:
Refactor the `audio_capture` module to support multiple, independent audio sources (microphone and system) and establish the new directory structure for storing audio.

Context:
This is the first step in enabling dual-source synchronized transcription. It lays the architectural foundation for handling microphone and system audio as separate streams. This BU focuses only on the structural changes and does not implement system audio capture itself.

Allowed Files:
- `src/audio_capture/core.py`
- `src/session/manager.py`

Dependencies:
Required:
- BU006

Blocks:
- BU009

Tasks:
- Modify `AudioRecorder` (or equivalent) to manage multiple recording threads/processes, one for each audio source (mic, system).
- Update the session creation logic in `SessionManager` to create the new audio directory structure:
  - `sessions/<session_id>/audio/mic/`
  - `sessions/<session_id>/audio/system/`
- The recorder for the microphone should continue to function as before, saving its audio to the new `mic` subdirectory.
- Add a placeholder for the system audio recorder, but do not implement it yet.

Out of Scope:
- Implementing the system audio capture logic.
- Chunked recording.
- Any changes to the transcriber.

Definition of Done:
[ ] `SessionManager` creates the `mic` and `system` audio subdirectories when a session starts.
[ ] The microphone recorder is operational and saves its audio file(s) to `sessions/<session_id>/audio/mic/`.
[ ] The architecture clearly supports adding a second, independent audio recorder for system audio.

Reviewer Focus:
- The directory structure is created correctly.
- The microphone recording works as expected within the new structure.
- The changes provide a clean interface for adding the system audio recorder in the next BU.
