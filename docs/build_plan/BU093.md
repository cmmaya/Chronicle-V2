# BU093 — In-Chat Scope Switch Prompt

Status:
Complete

Goal:
Render the BU092 scope offer as a themed prompt inside the conversation itself — "Would you like to change the scope to Specific for session: <Session Name>, <Session Date>?" with YES and NO buttons — so the user switches scope with one click in the chat instead of reading a separate candidate list, and so declining is a real, recorded answer rather than ignoring a panel.

Context:
BU090 answers a detail question in Any Session, appends a handoff note, and reveals the relabelled multi-session picker below the input bar (`_display_candidates` src/app/window.py:5008, `_on_use_candidate_clicked` src/app/window.py:5069, detached twins at src/app/window.py:5575 and src/app/window.py:5602). That works but lives outside the conversation and always asks the user to pick from a list. BU092 now supplies a single dominant session as `AnswerResponse.scope_offer`; this BU presents it in the chat flow. The conversation view is built from pixel-themed bubbles (`aligned_bubble` / `PixelBubble` src/app/pixel_widgets.py:350 and src/app/pixel_widgets.py:244, inserted by `_add_message_to_conversation` src/app/window.py:2852 and `_replace_thinking_message` src/app/window.py:2895); the detached window uses a plainer QFrame bubble (`_add_message_to_detached_conversation` src/app/window.py:2922). Accepting must reuse the existing re-ask path, which already forces `explicit_scope="current_session"` with a chosen session id. Scope combos are kept in sync through `_on_scope_changed` (src/app/window.py:3048) and `_on_detached_scope_changed` (src/app/window.py:3036) behind `_scope_sync_guard`. See docs/build_plan/ANY_SESSION_REFACTOR.md sections 2.5, 2.6 and 3.3.

Tasks:
- Add a pure `format_scope_offer_prompt(session_name, start_time) -> str` to src/assistant/scope_offer.py producing exactly `Would you like to change the scope to Specific for session: <name>, <YYYY-MM-DD HH:MM>?`, matching the date format already used by `_display_candidates`. A missing or unparseable `start_time` must drop the date and its comma rather than printing a placeholder.
- Add a `PixelScopePrompt` widget to src/app/pixel_widgets.py reusing the existing bubble language — same pixel-cut corners, left tail, blue variant colours, Courier New bold label — with two `PixelButton`s labelled `YES` and `NO` below the text. No dialog, no message box, no new colour tokens.
- Expose `accepted` and `declined` signals on the widget; the widget itself performs no application logic.
- Add `_add_scope_offer_to_conversation(offer)` to MainWindow, inserting the prompt into `_answer_layout` immediately after the answer bubble, using the same insert-before-stretch and scroll-to-bottom pattern as `_add_message_to_conversation` (src/app/window.py:2852).
- In `_on_assistant_query_finished`, when `response.scope_offer` is present, show the prompt and do **not** append the BU090 handoff note and do **not** open the multi-session picker. When it is absent, the BU090 behaviour must remain exactly as it is today.
- On YES: set the selected session to the offer's session, switch the scope combo to Specific Session, and re-ask the stored question with `explicit_scope="current_session"` and that session id — reusing the same call shape as `_on_use_candidate_clicked` (src/app/window.py:5069) rather than duplicating it.
- Switching the combo must go through the existing signal path so the detached combo, the transcript panel and the scope label all follow; respect `_scope_sync_guard` so the change does not recurse.
- On NO: call the BU092 `decline_scope_offer(conversation_id, session_id)` so the same session is not offered again in that conversation.
- After either answer, disable both buttons and collapse the prompt to a short static record of the choice, so the conversation still reads correctly on scroll-back but the prompt cannot be triggered twice.
- Retire any pending un-answered prompt when a new question is asked, so at most one live offer exists at a time.
- The prompt is transient UI only: never write it to `assistant_messages`, and never re-create it when a past conversation is reloaded into the view.
- Mirror the behaviour in the detached assistant window using its own bubble style (`_add_message_to_detached_conversation` src/app/window.py:2922) and plain `QPushButton`s, wired to the same accept and decline handlers.
- Keep the BU090 multi-session picker fully working for the ambiguous case and for the original clarification flow; this BU adds a path, it does not remove one.
